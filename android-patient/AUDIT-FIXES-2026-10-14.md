# 2026-10-14 审计修复交付

依据 `docs/CROSS-PLATFORM-AUDIT-2026-10-14.md`；基线为 `dba5204`。本轮按既定范围修改 Android 和影响两端的真实后端缺陷，没有修改鸿蒙实现。多 agent 分别负责 Android 数据层、后端和独立源码复核；协调者负责 Activity、布局、整合和提交。

## 已修改的路径

| 编号 | 修复 |
| --- | --- |
| F01 | 完整主诉先进入现有危急征象及否定规则；仅常规检索和模型输入截断，保留 truncated 标识。 |
| F02 | 病历保存和锁定以 draft 状态、七段文本的二进制比较、作者和时间组成同一条件更新快照。锁定校验的内容必须与更新命中的内容一致；并发变更返回 EMR_CHANGED/409，不覆盖用户的新输入。首次建单冲突也明确返回；预填仅参与实际建单。 |
| F07 | 按预约 ID 原子比较后清理幂等键；确认取消的 ID 持久保存，拒绝其迟到挂号响应。取消其他设备同排班订单不删除本机有效键。 |
| F10 | Android 分诊读取等待单独设为 45 秒；后端自 RAG 开始计 12 秒增强额度，扣除 RAG、配置和提示构建用时后，只等待剩余额度。并发许可满时直接规则降级；超时网络任务仍占许可直到退出，迟到结果不写响应。 |
| F11 | 在线登录不按登录时的旧本地期限自行清除。启动读取 auth/me，权威 401 清除，网络失败保留可恢复状态。个人页期限明确为登录时快照。 |
| F12 | API 30+ 根布局处理系统栏、缺口和输入法 Insets，使用绝对 padding 并消费 Insets，避免累积。旧版本保留框架窗口适配；Activity 明确 adjustResize。 |
| F16 | auth/me 解析姓名，仅在地址、令牌和患者身份仍匹配时写缓存，同步成功重绘。缺姓名字段的旧服务保留缓存值。 |

F02 使用乐观内容快照而非在共享数据库连接上增加跨请求事务。MySQL 二进制比较用于避免不区分大小写的排序规则误判文本版本；未增加表结构或迁移。

布局处理参考 [Android 官方 Views Insets 指南](https://developer.android.com/develop/ui/views/layout/edge-to-edge)，保留现有原生 Views 架构。

## 验证边界

本轮仅完成源码复核和差异检查。没有运行测试、构建、签名检查、业务 API、数据库或模拟器。旧 APK 不包含本轮修复；需要用户重新构建并测试。

用户回归重点：

1. 危急词位于长主诉末尾及截断边界，包含否定上下文；危急时不得进入常规模型或号源推荐。
2. 并发保存/锁定、锁定前清空必填、同秒不同大小写文本修改、无变化保存及并发首次建单；锁定病历完整且不可变，失败响应与数据一致。
3. 退其他设备的同排班 B 后重试仍重放 A；先取消响应尚未收到的 A，再挂 B，A 的迟到响应不能覆盖或清除 B；重启后继续满足这些约束。
4. 服务端续期超过旧本地期限后仍能恢复；真实撤销退出，断网不删会话；管理员改名同步后首页和个人页更新，旧账号/地址响应不能改新身份。
5. API 35 手势、三键、缺口屏、横向缺口及键盘弹出时按钮可见可点；API 26–29 保持原有窗口适配。
6. 模型延迟 16/21/30 秒、连接不可达及并发占满时收到规则降级；核对数据库查询耗时和两端等待余量。

## 保留事项

鸿蒙专属 F03/F04/F05/F06/F08/F09/F13/F14/F15 未在本轮修改。Android 公告功能缺口、鸿蒙名称展示、SSE 主诉方式统一和成功测试夹具的动态日期也保留后续处理；没有把它们标为已修复。

F10 的模型等待可以有界，但同步数据库查询不能由此机制中断；RAG 和基础 SQL 的锁等待/执行超时仍需部署侧配置和用户验证。因此不声称整个 HTTP 请求存在可证明的硬截止时间。

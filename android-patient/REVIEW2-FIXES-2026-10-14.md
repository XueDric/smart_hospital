# 第二轮修复交付（2026-10-14）

依据 `docs/CROSS-PLATFORM-REVIEW2-2026-10-14.md` 和用户提供的首轮审计附件。范围仍为 Android 与真实后端缺陷；鸿蒙源码只接收 main 的现有提交，不在本轮修改。国内镜像配置留在本地，未纳入提交。

## 修复与兼容约束

| 项目 | 处理 |
| --- | --- |
| R01 | HashMap 使用仓颉 `contains(k)`；同时接收 main 的同项修复，不使用 JsonObject/Java 的 containsKey 替代。 |
| R02 | MySqlBackend 全部查询、写入、结果物化和完整事务共用仓颉可重入 Mutex；事务开始持锁到提交或回滚，拒绝嵌套 BEGIN。非事务请求不能插入另一请求的事务。INSERT 与生成 ID 读取通过同一锁内 execInsert 原子执行，生产创建入口均改用它。 |
| R03/F07 | 取消确认只退休匹配的 completed ID，并保存取消 ID，保留原 token T。历史列表仅同步明确取消记录，不把 capped 200 列表中缺失当作取消。同 T 的成功 POST 返回新 B 时，在旧 A 快照匹配条件下原子接管并记录 A 已退休；迟到 A 不能覆盖 B，退另一设备订单不能删本机有效键。 |
| R04/F01/F10 | 完整主诉按 Rune 顺序匹配，每片段字符数组一次生成并复用，移除每次命中从头转换索引的二次复杂度。保留四字符否定窗口、高危优先及模糊词共现规则。增强截止提前到已授权请求开始，规则、查询和 RAG 用时从模型剩余额度扣除。 |
| F11/F16 | 继续以服务端身份判断在线会话，解析 main 新增的 expires_at，仅在原地址、token、身份仍匹配时同步缓存；缺字段或 0 保留原值。姓名同步与页面重绘逻辑保留。 |
| 数据库资源 | 为构造时会话设置、查询与写入的 Statement/QueryResult 增加 finally 清理，保持关闭操作在连接锁内，不关闭正常共享连接。 |

MySqlBackend 保留单连接实现以控制改动范围，SQL 操作串行是这一临时方案的吞吐限制。未引入连接池、表结构变更或新增外部依赖。仓颉 Mutex 使用本机 1.2.0 已有构造器、lock/unlock 和 synchronized；Statement/QueryResult 清理按本机 SQL 接口及内置 MariaDB 驱动确认。

execInsert 是本工程 DbBackend 默认方法，MySQL 实现用同一锁覆盖写入和 ID 读取；不会把原 exec 的“影响行数”当作新行 ID。已有参数绑定、转义和 SQL 会话模式保持原实现。

同 T 接管依赖既有后端约束：`(patient_id, client_token)` 唯一，取消时释放 client_token 为 NULL。同患者同号源的成功 POST 返回 B，是当前 T 已归属 B 的权威响应；接管还必须匹配发起时的 A 快照，不能任意覆盖后来完成的 C。

## 首轮附件复核

F01/F02/F07/F10/F11/F12/F16 对应后端及 Android 修复保留，本轮补其第二轮边界。第二轮 Android 使用 Asia/Shanghai 的设备日期，合入 main 的 today/timezone 接口但尚未消费健康日期；第三轮 T03 已改为实际读取医院 today 并删除设备时钟可售复判，见 REVIEW3-FIXES-2026-10-14.md。F03/F04/F05/F06/F08/F09/F13/F14（鸿蒙客户端）/F15 和第二轮 R05–R08 属鸿蒙专属，按用户再次确认的范围保留待处理，不标为已修。

main 的仓颉 API 修复、确定性日期夹具、续期有效期和医院日期接口，以及鸿蒙构建修复，逐处对照后合入；不重复实现或覆盖其更改。

## 验证与交付用户的判据

本轮完成多 agent 源码实现和独立源码复核、差异检查；没有执行编译、测试、探针、设备、业务 API 或数据库操作。报告中他人已有的构建/探针结果仅作兼容参考，不能当成本轮产物验证。

- 服务端按项目固定 cjc 1.2.0 + stdx 1.1.3.1 完整构建；确认新增数据库方法与 Statement 清理的类型兼容。
- 隔离数据库强制并发挂号、退号、病历保存及事务失败交错，确认回滚不影响别的请求、号源守恒、成功病历不被别人的回滚撤销、响应 ID 正确。覆盖嵌套 BEGIN 拒绝、提交/回滚失败和锁释放。
- 长驻服务反复查询/写入，观察预处理语句数量不持续增长。
- 取消 A 服务端提交后丢响应、外部取消、A 掉出 200 条历史、B 先到/A 晚到、退其他设备同排班订单、重启重登：只创建和重放期望订单，不创建额外 C。
- 纯危急检测覆盖长文本末尾危急词、重复否定、混合 UTF-8、四字符窗口和重叠命中；长度翻倍时不再出现旧的近四倍扫描工作量。
- 新旧 auth/me 响应、缺字段/0、滑动续期、撤销、地址/账号切换的延迟响应，均不误清或覆盖新会话。

12 秒仍为剩余模型增强额度；同步 SQL、锁等待和规则扫描不能被该机制强制中断，不宣称整个 HTTP 请求具有 12 秒硬截止。原 APK 不包含这些新改动，须用户重建与验证后再验收。

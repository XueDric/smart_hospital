## 一、9 分钟讲稿

### 第 1 段｜问题与形态（0:00–1:30）

- **要解决的不是"做个 App"，是"三端 + 服务端 + 契约"能不能在同一个真相上运转。**
  患者端（HarmonyOS ArkTS）、医生端/管理端（同一 App 内按角色分树）、安卓端（原生 Kotlin 对照实现）、服务端（**仓颉**）——四个产物共享同一套接口契约。
- **一条链路讲透**：主诉 → 分诊 → 推荐号源 → 挂号 → 就诊。每一步都由**服务端**裁决，客户端只呈现。
- **为什么用仓颉写服务端**：这是国产语言在真实业务里的落地尝试；我们不仅写业务，还**自己维护了 MariaDB 驱动**（`server/third_party/mariadb-driver`，47 个 `.cj`）——因为生态里没有能直接用的。
- 规模：REST **81** 个端点、契约 **24** 份 schema + **67** 个示例、服务端业务 **38** 个 `.cj`、鸿蒙 **62** 个 `.ets`、安卓 **5** 个 `.kt`。

### 第 2 段｜架构与取舍（1:30–4:00）

- **分层**：`http_*`（路由与解析）→ 领域（`triage_*` / `appointment` / `prescription` / `ai_*` / `kb_*`）→ 存储（`DbBackend` 抽象，MySQL 实现）。**没有 ORM**，SQL 集中且可审计。
- **三个"必须有"的取舍**（这是本项目的工程观点）：
  1. **AI 只能提议，不能决定。** 模型输出科室名后，服务端必须拿**真实号源库存**做校验；校验不通过就降级成"备选号源 + 说明"。所以"AI 说去哪科"永远不会把患者导到一个没号的科室——这也是演示里那句「本院暂未开诊「消化内科」，以下科室当前有号」的来源。
  2. **凡是模型调用，必须能一条命令证明它真的调了。** `triage_stat` 记 `source`（`model` / `rules` / `model:invalid`），看板按**分布**统计而不是写死——原实现把 `source` 硬编码成 `rules`，等于系统自己在撒谎说"AI 没被调用"，我们把这行删了（[整改方案 §3.4](整改方案-2026-10-17.md)）。
  3. **密钥只存引用。** 库里永远只有 `env:` / `file:` / `builtin:demo`，没有裸密钥；`builtin:demo` 是为了"装完即能真调"，代价是它随源码分发，所以**发布前必须轮换**（写在代码注释与合规记录里）。
- **契约先行**：`contract/schema` + `contract/examples` 是四端共同真相；改接口先改 schema，再跑 `accept`。

### 第 3 段｜AI 这条线的真本事与真边界（4:00–6:00）

- **能调**：默认配置（`ai.enabled=1` + `builtin:demo` + DeepSeek `deepseek-chat`）装完即可真调；`ai-live-check.ps1` **25 项断言全绿**，含 `probe.ok=true / http_status=200`、`source=model`、响应里搜不到 `sk-…`。
- **稳**：出站带重试（429/5xx/网络异常，退避 200 ms）+ **全链路墙钟上限**（框架没给 `connectTimeout`，我们用 `Future.get(timeout)` 等价覆盖，注释里写清"超时不取消 TCP"这个残留）；失败一律降级到规则，用户端不报错。
- **安全分诊规则是独立一层**（`triage_redflag.cj`）：红牌词 + 模糊词 + 否定窗口 + 强度词共现。评审指出两处可复现缺陷（否定只回看 4 字、强度词裸子串），我们改成 **8 字窗口 + 分句边界**、把强度词拆成**急迫/慢性两组**并要求 **≤6 字共现**，另补 22 组同义词（胸口疼、气短憋气、痰中带血…）。`triagetest` 从 110 → **139 项**。
- **边界（主动说）**：向量检索目前是**演示向量**（默认已指向真实 embedding 端点，但检索算法没接）；三张 Prompt 表和 6 个工具开关还没接消费端。这两块我们没做，理由写在 [整改方案 §5.1](整改方案-2026-10-17.md)：它们会牵动"Prompt 版本进日志/审计"，属于独立一批。

### 第 4 段｜能装、能跑、能验（6:00–7:30）

- **构建**：`.\hvigorw.bat … assembleHap` → `BUILD SUCCESSFUL`。仓库里刻意不含证书，产物是**未签名 HAP**（`WARN` 是预期的），模拟器可直接安装。
- **运行**：华为模拟器 Pura 90（HarmonyOS 6.1.1 / API 24）上跑通**患者全流程**与**管理端真实聚合**，10 张截图在 [release/harmony/screenshots](../release/harmony/screenshots/)，每张都有对应 `dumpLayout` 文本实测（不是只截图）。
- **验**：`accept` **777 项 / 0 失败**，且**故意把夹具弄脏后重跑仍然 777/0**（评审指出过 "accept 对脏库敏感"，我们把夹具改成幂等写入）；`triagetest` 139、`selftest` 51、`authtest` 17、REST 81；`final-verify.ps1` 一条命令 18 项逐项 `EXIT=0`。
- **门禁**：`tools/check-docs.ps1`（相对链接 / `.ps1` 必须 UTF-8 BOM / `.bat` 纯 ASCII / 旧中文路径零残留）已进 CI；`doc-counts.ps1` 进 `final-verify`——**文档里的数字必须是跑出来的**，不是抄的。
- **跑起来才发现的三条缺陷**（很值得讲）：① 三端 `register*Feature()` 各自 `replace` 登录页，最后一个赢 ⇒ 全新安装永远进管理端，患者主流程界面上不可达；② 「同步身份信息」只同步角色/档案号，不同步姓名；③ 仓颉 stdx 走 OpenSSL、**不读 Windows 证书存储** ⇒ AI 出站 `134 unknown CA`，而 `curl` 一切正常。三条都不是"写代码时能想到"的，是"必须真跑"才会暴露的。

### 第 5 段｜诚实收尾（7:30–9:00）

- **做到了**：四端可构建、患者全流程可运行、AI 默认真调且有断言、777/139 断言可复现、数字与文档同源、分发包含许可文件、令牌进安全存储（HarmonyOS `AssetStoreKit` / Android `AndroidKeyStore` AES-GCM）、主题切换不再重建整树。
- **没做到（明确列出）**：客户端自动化测试仍为 **0**（见 [整改方案 §4.3](整改方案-2026-10-17.md)：要 Hypium + `ohosTest` 脚手架，我们选择"先给可比的行为证据"而不是半成品脚手架）；向量检索是演示向量；Prompt 表/工具开关未接消费端；i18n 与无障碍为 0（约 750 处中文字面量）；服务端套件未上托管 CI（缺 cjc 环境，写进 workflow 注释而不是造一个假绿灯）。
- **下一步（有时间线）**：客户端纯函数单测 30–50 条 → 向量检索接真 embedding → Prompt 版本进调用日志 → 生产密钥轮换 + Q6 复核。

## 二、现场演示脚本（3 条命令）

> 演示前 5 分钟预热：模拟器已启动、服务端已跑起来（见下）。**任何一步失败时用什么话兜住**，写在每步后面。

### 步骤 1：证明构建是真的（约 25 s）

```powershell
.\hvigorw.bat --mode module -p product=default -p module=entry@default assembleHap --no-daemon
```

期望：`BUILD SUCCESSFUL`，HAP 落在 `entry\build\default\outputs\default\entry-default-unsigned.hap`。
兜底话术：切到 [release/harmony/build-log-2026-10-17.txt](../release/harmony/build-log-2026-10-17.txt) 看完整日志（ANSI 已剥离）与 HAP 的 SHA256。

### 步骤 2：证明 AI 真的调了（约 40 s）

```powershell
# 先在服务端窗口导一次 CA（换过网络才需要重导）
powershell -NoProfile -ExecutionPolicy Bypass -File .\server\export-ca-bundle.ps1
$env:SSL_CERT_FILE = "$PWD\server\ca-bundle.pem"
.\server\build\hospital-server.exe serve "mysql://hospital:hospital_dev_2026@127.0.0.1:3317/hospital_test"

# 另一个窗口
.\server\tests\ai-live-check.ps1 -AdminPw <管理员口令>
```

期望：`25 项全 PASS`；其中 `probe` 行形如 `{"ok":true,"http_status":200,"model":"deepseek-chat",…}`，`source=model`，`ai_note` 是模型生成的文本。
兜底话术：若报 `134 unknown CA`，说明 `SSL_CERT_FILE` 没设——这正是我们文档里写的"仓颉走 OpenSSL、不读 Windows 证书存储"。
**密钥不投屏**：`ai.key_ref` 只显示 `builtin:demo`，任何响应里都不会出现 `sk-…`。

### 步骤 3：证明流程与数据是真的（约 60 s，模拟器上操作）

1. 患者端登录（`13800000000` / 演示口令）→ 首页 `您好，演示患者`。
2. 分诊页输入 `腹痛拉肚子两天` → **判断依据：① 推荐来源：模型增强 ② 校验结果：推荐备选号源 ③ 可用号源：1 个，均来自服务端实时校验**。
3. 点「选择该号源」→「确认挂号」→ `挂号成功：2026-12-24 上午，序号 1`。
4. 底部「就诊」→ 当前预约 `序号 1 · 内科 · 张医生 主任医师 / 已挂号`。
5. 切管理端（登录页「管理端登录」）→ 运营看板：`AI 模型 deepseek-chat · 工具 6/6`，聚合卡片与刚才的操作对得上。

兜底话术：网络断了就切「演示数据」开关（同一套 UI，走 Mock）；或直接放 [release/harmony/screenshots](../release/harmony/screenshots/) 的 10 张实拍。

### 步骤 4：证明"数字不是抄的"（约 90 s，可跳过）

```powershell
.\server\tests\doc-counts.ps1        # 文档里的 777 / 139 / 81 是否与实测一致
.\tools\check-docs.ps1               # 链接 / BOM / ASCII / 旧路径 四项门禁
```

期望：`✅ 文档数字与实测一致`；`check-docs` 全绿（184 条相对链接）。

## 三、12 个高概率追问

| # | 追问 | 回答口径 |
|---|---|---|
| 1 | **AI 会不会瞎推荐科室？** | 会提议，不会决定。模型只产出科室名，服务端必须用真实号源库存校验；不通过就降级为"备选号源 + 说明"。演示里那句「本院暂未开诊「消化内科」」就是校验结果。 |
| 2 | **模型挂了怎么办？** | 降级到规则分诊（`source=rules`），用户端不报错；出站有 1 次重试（429/5xx/网络异常）+ 全链路墙钟上限（默认 30 s）。 |
| 3 | **怎么证明 AI 真被调用了？** | `ai-live-check.ps1` 25 项断言 + `triage_stat.source` 分布 + 看板 `by_source`。原实现把 `source` 写死 `rules`，我们删了这行——**系统不能自证没调 AI**。 |
| 4 | **密钥怎么管的？** | 库里只存引用（`env:` / `file:` / `builtin:demo`），永不存裸密钥；`builtin:demo` 是演示密钥，随源码分发，**发布前必须轮换**；生产用 `env:` 注入。 |
| 5 | **为什么把默认值从关闭改成开启？** | 评审原话是"默认零模型调用"。我们改成"演示默认开、生产必须换 key 或置 0"，并把这条决策写进 `docs/Q6-合规决策记录.md`——不是偷偷改默认值。 |
| 6 | **红牌分诊是不是关键词匹配？** | 是规则层，但经过三轮修正：否定窗口 8 字且不跨分句、强度词分急迫/慢性两组并要求 ≤6 字共现且自身未被否定、22 组同义词扩充；`triagetest` 139 项覆盖这些反例（如「一直头晕」「没有胸口疼」不报红牌）。 |
| 7 | **三位端首屏为什么一开始是管理端？** | 三个 `register*Feature()` 各自 `replace` 登录页，最后调用的（admin）赢。这是"真跑才看得见"的缺陷，已改为"注册不导航 + 三个登录页互相给入口"。 |
| 8 | **为什么没有客户端单测？** | 0，如实说。鸿蒙要走 Hypium + `ohosTest` 脚手架（要 `ohpm` 装包、设备上 `aa test`），半成品比没有更糟；本轮给的是**可比较的行为证据**（10 张实拍 + `dumpLayout` 文本）。下一步先抽纯函数再上单测。 |
| 9 | **CI 里为什么不跑服务端套件？** | 需要 cjc 1.2.0 + stdx 1.1.3.1 + 自编 MariaDB 驱动 + MySQL 实例，托管 runner 装不全。我们只把"不需要编译器"的四项卫生门禁上了 CI，并在 workflow 注释里写明原因，而不是造一个必然被绕过的红灯。 |
| 10 | **向量检索是真检索吗？** | 不是。目前是演示向量，默认播种已指向真实 embedding 端点（百练 `text-embedding-v3`），但入库/检索/降级没接。管理端与文档都标明"演示用假向量"。 |
| 11 | **为什么用仓颉？** | 真实业务里验证国产语言：38 个业务 `.cj` + 自维护 MariaDB 驱动 + 轻舟 HTTP 框架；也踩到了真实生态缺口（`stdx.net.http` 无 `connectTimeout`、OpenSSL 不读 Windows 证书存储），这些都被写进文档而不是绕过去。 |
| 12 | **你觉得这套东西最脆的地方是什么？** | 三处：① 客户端零自动化测试，回归只能靠人跑；② 假向量 + 真 embedding 端点之间的半截状态最容易被误解成"能检索"；③ 演示密钥 `builtin:demo` 一旦忘记轮换就是事故。三条都写进了"没做到"清单。 |

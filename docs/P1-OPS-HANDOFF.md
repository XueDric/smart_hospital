## 一、证书信任分发（换受信任 CA）

### 现状

- 服务端用 `server/new-tls-cert.ps1` 生成的**自签**证书（含 SAN，覆盖 `localhost` + 本机各 IP）。
- 客户端要想不报证书错误，**必须显式信任**这张自签证书。
- 实测确认的老问题（写在 [P1-HANDOFF.md §5](P1-HANDOFF.md)）：Windows 的 curl 走 **Schannel**，
  对自签证书的 `--cacert` 支持不完整（`schannel: error 0x00000010`），
  所以 `tests\tls-check.ps1` 改用 .NET `SslStream` + 显式链校验 + 自解析 SAN。

### 为什么本机做不了

1. **没有受信任 CA**：本机只有自签证书；签发受信任证书要么有院内 CA，要么买公网证书。
2. **不能改系统信任库**：把证书装进"受信任的根证书颁发机构"需要**管理员权限**，
   且会改变**系统状态**（本会话实测卡在提权，已确认无残留）。
   —— 这是**刻意不做**的：agent 不应擅自修改用户的系统信任配置。
3. **客户端侧（鸿蒙）无法在本机验证**：`entry/` 目前尚不存在（见根 README 目录结构），
   没有可跑的客户端来验"它能信任这张证书"。

### 判据（做完后拿什么证明）

| # | 判据 | 怎么验 |
| --- | --- | --- |
| 1 | 证书链能到**受信任根**（不再是 `UntrustedRoot`） | `tls-check.ps1` 的链校验层：把 `AllowUnknownCertificateAuthority` 去掉后仍 `Build = True` |
| 2 | 主机名匹配（SAN 覆盖实际访问用的名字/IP） | `tls-check.ps1` 第 [2] 段（已在跑） |
| 3 | **不依赖 `-k` / `insecure`** 能完成一次业务请求 | `curl` **不带** `-k` 调 `/health` 返回 200；或客户端真机跑通登录 |
| 4 | 客户端（鸿蒙）真机能登录并挂号 | 需 `entry/` 存在后单独验 —— **当前不存在，故此项无法进行** |

### 具体做法（三选一，按院内条件）

```powershell
# ① 有院内 CA（推荐）：
#    用院内 CA 签发一张给本服务的证书，SAN 填实际访问用的域名/IP。
#    把 CA 根证书分发给客户端（鸿蒙侧装到信任库 / 或系统级）。
#    服务端只换 cert/key 两个文件即可，代码零改动：
server\new-tls-cert.ps1          # 仅作占位；换成院内 CA 签发的 cert.pem / key.pem
.\build\hospital-server.exe serve <dsn> --port 8443 `
    --tls-files "C:\ProgramData\smart-hospital\tls\tls.env"

# ② 内网无 CA、但能装根证书：
#    沿用例①的自签流程，但把 cert.pem 作为**根**分发到客户端信任库。
#    ⚠ 这只解决"客户端不报错"，不是真正的公信力（任何拿到私钥的人都能签发）。

# ③ 公网域名 + 公网 CA：需要真实域名与 80/443 可达（本机环境不具备）。
```

### ⚠ 换证书时必须一并注意

- **证书路径必须是纯 ASCII**：仓颉运行时无法接受含非 ASCII 的 argv
  （本仓库路径含中文 ⇒ 必然失败），所以走 `--tls-files` 指向
  `%ProgramData%\smart-hospital\tls\tls.env`（见 [P1-HANDOFF.md §5.4](P1-HANDOFF.md)）。
- 换证书后**必须重跑** `tests\tls-check.ps1`：新证书的 SAN 未必覆盖你实际用的地址。
- `serve` 的 fail-closed 行为不要动：证书/私钥缺失或 PEM 非法一律**拒绝启动**，
  绝不静默降级成明文（四条已实测，见 P1-HANDOFF §5.2）。

## 二、证书轮换与到期监控

### 现状

- 证书有效期 **3 年**（`new-tls-cert.ps1` 生成时 `+3 年`），**靠人记**。
- 到期那天服务**照常启动**（TLS 握手时客户端报错），没有预警。

### 为什么本机做不了

"监控"的价值在于**长期运行 + 告警通道**：本机是开发环境、进程随时重启，
没有告警接收方（邮件/IM/监控平台），做出来的只是一个没人看的检查。

**但"检查"本身可以做**——所以这一半我做掉了（见下），**另一半（告警接入）留给运维**。

### ✅ 本机已完成的一半：可查询的到期检查

```powershell
# 读证书并算剩余天数（exit code 非 0 = 已过期或即将过期，可直接进 CI/监控）
.\server\tests\tls-check.ps1 -Cert "C:\ProgramData\smart-hospital\tls\cert.pem" `
    -Host_ 127.0.0.1 -Port 8443
# 第 [1] 段会断言"当前时间在有效期内"，并打印 NotBefore → NotAfter
```

`tls-check.ps1` 第 [1] 段已经包含有效期断言。**到期即变红**，可直接接进任何调度器。

### ⚠ 仍需要运维做的

| # | 待办 | 判据 |
| --- | --- | --- |
| 1 | 把上面的检查**接进调度器**（每日一次），失败**告警到人** | 有人真的会收到告警（不是写进日志了事） |
| 2 | **提前 30 天**开始告警（3 年期证书，等到期当天才发现就晚了） | 告警阈值可配；用一张快过期的测试证书验证过会响 |
| 3 | 轮换**流程**：新证书签发 → 部署 → 重启 → 复验 → 旧证书下线 | 在**非生产**窗口演练过至少一次（含回滚） |
| 4 | 私钥**分发与保存**规范 | 私钥不入库（`.gitignore` 已排除 `*.pem`/`server/certs/`）、不进聊天工具、有访问控制 |

> 📌 关于第 2 条：本例程的检查是"当前是否在有效期内"，**不区分**"还有 2 年"
> 和"还有 2 天"。要提前告警，需要在调度侧按 `NotAfter` 算差值 ——
> 或者告诉我，我把阈值检查加进 `tls-check.ps1`（属代码改动，可做）。

## 三、这一节为什么单独存在（方法论）

P1-HANDOFF §9 把剩余项混在一张表里，其中：
- 代码类（口令强度 / 令牌按设备 / 我的挂号 / 排班列表）→ **已全部完成**；
- 运维类（本文两条）→ **本机不可验证**。

把两类混在一起的风险是：**"剩下的都不太重要"**这种错觉 ——
而"证书信任"恰恰是"HTTPS 到底有没有用"的分水岭（自签+不信任 ≈ 只防了被动窃听）。
所以单独成文，并把判据写到"能拿什么证明"的粒度。

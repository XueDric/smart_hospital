## 1. 项目概览

**项目名**：智慧医院智能导诊就诊系统
**一句话闭环**：患者输入一句主诉 → AI 多步推理取证 → 推荐科室与医生 → 校验真实有号 → 一键挂号 → 医生接诊 → 生成电子病历，**全程落库、可追溯、可观测**。

**三端角色**（服务端单一权限矩阵 `can(role, action)` 强制）：

| 角色 | `role` 值 | 档案 id | 能做什么（概要） |
| --- | --- | --- | --- |
| 患者 | `patient` | `patient.id` | 分诊 / 预问诊 / 挂号 / 退号 / 读自己的病历与挂号 |
| 医生 | `doctor` | `doctor.id` | 接诊队列 / 写自己的病历 / 读知识库 / 看排班 |
| 管理员 | `admin` | `0` | 基础数据 CRUD / AI 能力中心 / 知识库 / 运营看板 / 退任意号 / 解锁病历 |

> ⚠ **判角色只能看 `role`**，绝不能用登录响应里的 `patient_id`（医生登录时它等于 `doctor.id`，管理员时为 `0`）。

## 4. 前后端划分方式

**本仓库是「后端唯一、前端留白」的结构**：

| 侧 | 现状 | 边界 |
| --- | --- | --- |
| **后端** | ✅ 已完成 P0–P5：挂号闭环 / 令牌鉴权 / HTTPS / AI 分诊 / 预问诊 SSE / AI 能力中心 / 电子病历 / 运营看板 / RAG 知识库 | 提供 **55+ 个 REST**（含 `/health`），三端权限由**单一函数** `can(role, action)` 强制 |
| **前端** | ⏳ 待实现：**鸿蒙患者端**（ArkTS）+ 管理端（另立一期） | 只消费后端 HTTP 契约；**不得**出现患者无权调用的路径（`/admin/**`、`/doctor/**`） |

**前后端契约边界（关键约定）**：

1. **业务接口全部带前缀 `/api/v1`**；唯一例外是 `GET /health`（根路径、不鉴权、不走信封）。
2. **成功信封** `{"ok":true,"data":{…}}`（200/201）；**失败信封** `{"ok":false,"error":{code,message,fields?}}`。
3. 框架层还有**两种平铺失败形状**（无 `ok`）：请求体非法 JSON → `{"code":400,"message":"Invalid JSON body","data":null}`；路径不匹配 → `{"error":"Not Found","path":"…"}`。**解析必须先判 `ok` 字段存不存在**。
4. **挂号与 AI 调用必须在线直连，绝不进离线队列**（离线补发会造脏单 / 状态污染）。
5. **release 必须走 HTTPS**（处理患者标识与病历正文）；服务端 TLS **绝不静默降级**，前端不能靠探测判断协议。

## 5. 路由与状态管理方案

### 5.1 服务端路由（已实现）

- **框架**：轻舟的 **Trie 路由**（`Router`），`buildHospitalRouter()` 集中注册；P4/基础数据/知识库三块通过 `registerP4Routes` / `registerBaseRoutes` / `registerKbRoutes` **登记**（便于端点计数对账）。
- **中间件顺序**（洋葱模型，有硬性理由）：
  `requestId → logger → contentLengthLimit(64KiB) → bodyParser → cors → timeout(15s) → router.middleware`
- **鉴权**：`principalOf(ctx, gate, auth)` 从 `Authorization: Bearer <token>` 解析身份（令牌优先；`--dev-auth` 下的 `X-Role`/`X-Patient-Id` 仅为开发态临时形态）。
- **无"服务端状态管理"概念**：HTTP 无状态，**MySQL 是唯一权威**（会话状态落库，进程重启不丢）。

### 5.2 前端路由与状态管理（待实现，方案已定）

> 依据 [`docs/分工.md`](分工.md) 的既定约束：

| 主题 | 方案 |
| --- | --- |
| **工程结构** | `entry`（壳工程）+ `common-core`（公共层）+ `feature-*`（功能模块）。依赖单向：`app → feature → common-core`，**业务模块之间禁止互相 import** |
| **路由** | 各 feature 模块向 `common-core` 中的 **统一路由注册表**注册页面；`Router` 集中管理 |
| **状态管理** | **ArkTS 状态管理 V2**（`@Local` / `@Param` / `@Event` / `@Provider` / `@Consumer`），**避免 V1/V2 混用** |
| **网络层** | 统一 HTTP 客户端 + **Bearer Token 注入** + **SSE 流式解析**（预问诊打字机） |
| **持久化** | 偏好存储 / 文件存储；**登录态持久化只存 `token` + `expires_at` + `role` + `ref_id`，绝不存口令** |
| **登录态** | Token 刷新（服务端滑动续期，**无 refresh 接口**）、登录拦截、401 统一踢回登录页 |
| **主题** | 深色/浅色模式切换（颜色资源体系，禁止硬编码色值） |

## 6. 数据模型

**共 14 张表 / 7 个域**（`server/src/schema.cj`）。★ = 走直接 SQL 的「业务状态」表。

| 域 | 表 | 关键字段 | 说明 |
| --- | --- | --- | --- |
| **基础数据域** | `department` 科室 | `id, name, code, location, sort, enabled` | `name`/`code` 均唯一（分诊按科室名查，重名会分裂口径） |
| | `doctor` 医生 | `id, name, department_id, title, specialty, enabled` | |
| | `patient` 患者档案 | `id, phone, name, gender, birth_date` | 敏感个人信息；**不存**身份证明文 |
| **号源域** ★ | `schedule` 排班/号源 | `id, doctor_id, department_id, work_date, period, total_num, remain_num, version, enabled` | `remain_num` 是防超卖支柱（原子自减） |
| **挂号域** ★ | `appointment` 挂号单 | `id, schedule_id, patient_id, doctor_id, department_id, visit_date, period, seq_no, status, client_token, slot_restored` | `visit_date` 是**就诊日快照**；`client_token` 幂等键（退号置 NULL）；`status`: `booked/visiting/done/cancelled/no_show` |
| **病历域** | `medical_record` 电子病历 | `id, appointment_id, patient_id, doctor_id, chief_complaint, present_illness, past_history, allergy_history, physical_exam, diagnosis, treatment, status, updated_by` | 七段式；`status`: `draft/locked`；**锁定后不可改** |
| **鉴权域** | `auth_user` 账号 | `id, login_name, role, ref_id, display_name, pw_salt, pw_hash, pw_iter, status` | 患者用手机号；医生/管理员用工号 |
| | `auth_token` 令牌 | `token, user_id, expires_at, last_renew_at, device_id, device_name, last_seen_at` | 有状态；`device_*` **不可信**，仅用于会话列表展示 |
| | `auth_login_attempt` 登录失败计数 | `login_hash, fail_count, window_start, last_fail_at` | 键是**登录名哈希**（防枚举） |
| **预问诊域** | `previsit_session` 预问诊会话 | `id, patient_id, turn, form_json, created_at, updated_at` | `id` 是 64 hex 字符串（全项目唯一的字符串型 id） |
| **AI 配置域** | `ai_setting` KV | `k, v, updated_at` | 写库即失效缓存 ⇒ **改配置零重启**；密钥**只存引用**不落库 |
| **统计域** | `triage_stat` 分诊统计 | `created_at, source, reason_code, red_flag, department, truncated` | **只存结论计数，不含任何患者标识**（180 天 TTL） |
| **知识库域** | `kb_doc` 文档 | `id, title, category, body, enabled, updated_by` | `title` 唯一（防两份矛盾文档） |
| | `kb_chunk` 切块 | `id, doc_id, seq, content, chars, embedding, embedded_at` | `embedding` 存 JSON 数组，允许 NULL（关键词路不需要向量） |

**通用约定**：所有 id 为 **JSON number（Int64）**，唯 `previsit.session_id` 是字符串；时间戳一律 **Unix epoch 秒**；日期是 `YYYY-MM-DD` 字符串。

## 7. 接口约定

**Base**：`http://<host>:<port>`（默认端口 **8080**；联调常用 `8091` 明文 / `8443` TLS，都是启动参数约定）。
**鉴权头**：`Authorization: Bearer <64 hex>`（头名 / `Bearer` 前缀大小写不敏感）。
**设备头**（可选、不可信）：`X-Device-Id` / `X-Device-Name`（各截断 64）。

**信封**：
```jsonc
// 成功 200 / 201
{ "ok": true, "data": { /* … */ } }
// 业务失败
{ "ok": false, "error": { "code": "SLOT_GONE", "message": "号源已被抢完，请选择其它排班" } }
// 框架层失败（无 ok / 无 error）
{ "code": 400, "message": "Invalid JSON body", "data": null }
{ "error": "Not Found", "path": "/api/v1/aprpointments" }
```

**HTTP 状态码给网络层用，`error.code` 给业务层用**。401 直接踢登录页；429 读 `retry-after` 退避。

**分页/限额**：**没有** `page`/`cursor`/`total`，只有 `limit`（超限**静默夹住**），靠 `count == limit` 粗判"可能还有更多"。

**端点全貌（56 条路由，含 `/health`）**：

| 分组 | 前缀 | 权限 | 条数（约） |
| --- | --- | --- | --- |
| 探活 | `GET /health` | 无 | 1 |
| 鉴权 | `/api/v1/auth/**` | 任意角色 | 6 |
| 患者业务 | `/api/v1/triage`、`/api/v1/previsit/**`、`/api/v1/schedules**`、`/api/v1/appointments**`、`/api/v1/medical-records**` | 患者（排班三端可读） | 11 |
| 医生业务 | `/api/v1/doctor/visits**` | 医生 | 8 |
| 管理端 | `/api/v1/admin/**` | 管理员 | 29 |
| 知识库检索 | `GET /api/v1/kb/search` | 管理员 + 医生（**患者 403**） | 1 |

> ⚠ **患者端不得出现** `/admin/**` 与 `/doctor/**` 的路径。用管理员账号登患者端去点分诊报 **403 是正常的**，不是 bug。

## 10. 结论与建议

1. **后端已完全就绪**：P0–P5 全部完成，55+ REST 端点带测试保护；前端只消费契约即可开工，**不需要等服务端补接口**（唯二建议补的是「患者可读的科室/医生列表」，否则 P-4 只能从分诊进入）。
2. **MVP 就是患者端 6 页**：登录 / 分诊 / 预问诊 / 约号 / 我的预约 / 我的 —— 与仓库已决事项 Q3 一致。
3. **三条红线必须守住**：① 分诊 `red_flag` 只引导急诊、绝不拼号源；② 挂号 `client_token` 幂等（重试复用、换号源换新 token）；③ 挂号/AI **在线直连不进离线队列**。
4. **SSE 是最容易做错的一环**：严格 `\n\n` 分帧 + 整段 UTF-8 解码 + `session_id` 持久化复用。
5. **管理端另立一期**：服务端接口已全部就绪（看板/基础数据/AI 中心/知识库），技术栈由前端方决定。

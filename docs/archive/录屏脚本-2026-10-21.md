> 目标：**一遍过、不分段拼接、全程「在线服务」（真实后端 + 真实 AI）**，总长 **5:40 左右**（落在评审建议的 3–5 分钟上限附近，比上一版 4:45 多出安卓段）。
> 本文 §6 记录的是**已交付成片**（2026-10-21 在线服务版，5:23）的规格、时间轴与已知边界；§6.7 存档的是 2026-10-20 的 Mock 演练稿。

## 0. 录前准备（不进画面，但必须做完）

### 0.1 环境一条龙

```powershell
cd E:\harmonyOS\smart_hospital\server

# ① 起库（本机 3317 被占过，固定用 3417）
.\devdb.ps1 start -Port 3417

# ② 编服务端（若 build 目录在可跳过）
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1

# ③ 导出 CA 包（仓颉 stdx 走 OpenSSL，不读 Windows 证书库；缺它会 134 报错）
.\export-ca-bundle.ps1
$env:SSL_CERT_FILE = "E:\harmonyOS\smart_hospital\server\ca-bundle.pem"

# ④ 起服务（这个窗口要录进画面）
.\build\hospital-server.exe serve "mysql://hospital:hospital_dev_2026@127.0.0.1:3417/hospital_test" --port 8091

# ⑤ 另开窗口确认
curl.exe -s http://127.0.0.1:8091/health
```

启动日志里必须能看到这两行（**这是"AI 真的接上了"的硬证据**，要录进画面）：

```

AI：**已启用** — 模型「默认对话模型」，endpoint https://api.deepseek.com/chat/completions，密钥引用 builtin
```

### 0.2 造演示数据（管理端接口，幂等，可重复跑）

```powershell
$base = 'http://127.0.0.1:8091'
$pw   = '<用 create-admin 打印的口令>'      # 只显示一次，注意别录进画面
$tok  = (Invoke-RestMethod -Method Post "$base/api/v1/auth/login" -ContentType 'application/json' `
        -Body (@{ login_name='admin'; password=$pw } | ConvertTo-Json) ).data.token
$H    = @{ Authorization = "Bearer $tok" }
$today = (Get-Date).ToString('yyyy-MM-dd')

# 内科（已存在会 409，忽略）
try { Invoke-RestMethod -Method Post "$base/api/v1/admin/departments" -Headers $H -ContentType 'application/json' `
  -Body (@{ name='内科'; code='NK'; location='门诊楼 2F' } | ConvertTo-Json) } catch { }

# 张医生（记下 data.id，下面要用）
$doc = Invoke-RestMethod -Method Post "$base/api/v1/admin/doctors" -Headers $H -ContentType 'application/json' `
  -Body (@{ name='张医生'; department_id=1; title='主任医师'; specialty='常见内科疾病' } | ConvertTo-Json)
$docId = $doc.data.id

# 今天上午的号源（关键：就诊日不能是未来——到院/候诊/接诊会被 `VISIT_DATE_FUTURE` 409 挡住；建排班只拦"早于今天"）
Invoke-RestMethod -Method Post "$base/api/v1/admin/schedules" -Headers $H -ContentType 'application/json' `
  -Body (@{ doctor_id=$docId; department_id=1; work_date=$today; period='AM'; total_num=5 } | ConvertTo-Json)

# 患者账号（ref_id 必须对应真实 patient 行；本库 patient id=1 = 13800000000）
try { Invoke-RestMethod -Method Post "$base/api/v1/admin/users" -Headers $H -ContentType 'application/json' `
  -Body (@{ login_name='13800000000'; password='Patient123'; role='patient'; ref_id=1; display_name='演示患者' } | ConvertTo-Json) } catch { }

# 医生账号（管理员建，ref_id = 上面医生 id）
try { Invoke-RestMethod -Method Post "$base/api/v1/admin/users" -Headers $H -ContentType 'application/json' `
  -Body (@{ login_name='e2e_doc'; password='Doctor123'; role='doctor'; ref_id=$docId; display_name='张医生' } | ConvertTo-Json) } catch { }
```

> ⚠ 跑过 `accept` 验收套件后库会被重置，上面四步必须重跑一遍（幂等，重复跑不会炸）。
> ⚠ 口令/令牌**不要**出现在画面里：用单独的 PowerShell 窗口跑，录屏前把它挪开或最小化。

## 2. 逐句字幕稿（可直接当配音稿）

1. 先起库、起服务。服务端是单个 exe：仓颉写的业务代码，加轻舟框架，MariaDB 驱动静态链接进去。
2. 自检接口如实报告数据库与 AI 状态；注意这一行——AI 已启用，密钥是"引用"，库里没有密钥本体。
3. 患者端覆盖智能分诊、预问诊、预约挂号、医疗档案。
4. 输入症状，服务端调模型；模型只负责给解释，科室和号源由规则引擎加服务端实时校验决定。
5. 选号、确认，扣号是数据库里的原子自减，不是前端动画。
6. 预问诊把结构化病史提前采集，医生端可以一键预填。
7. 医生端按状态机推进：到院、候诊、接诊、写病历、提交锁定。
8. 病历七段必填，锁定后不可改；解锁重写是管理员动作，而且要填理由。
9. 每次保存都有修订记录，可追溯到人。
10. 管理端看板全部来自真实表计数，响应里不含任何患者身份字段。
11. 模型配置、Prompt 模板、工具开关都在这一个页面；密钥只存引用。
12. 知识库按 400 字切块，检索当前走关键词路，向量路已实现但还没接线——这一点我们写在文档里，不藏着。
13. 安卓端与鸿蒙共用同一服务端、同一契约；同样的数据在另一端立即可见。
14. 主题切换立即生效，明暗判定只有一处。
15. 代码、契约、文档与构建证据都在仓库里。

## 3. 失败兜底（现场卡住时说什么）

| 症状 | 台词 |
| --- | --- |
| 分诊超过 30 秒没回 | "模型有全链路时限，超时会降级为规则，并把原因写进 `ai_reason`——这是设计好的降级路径，不是崩了。" |
| 分诊结论出现 `推荐来源：规则引擎` | "这次模型没给可用结论，走了规则兜底；结论里的判断依据会如实标明来源。" |
| 挂号报 `SLOT_GONE` | "号被抢了，服务端拒绝而不是超卖；刷新后余量是新的。" |
| 医生端「到院登记」报红条"该号的就诊日不是今天" | "服务端有就诊日期硬门槛，未来日期的号不能到院或接诊——这是防误操作。" |
| 安卓端中文输不进去 | "安卓模拟器不支持中文输入，分诊演示放在鸿蒙端；两端跑的是同一套接口。" |

### 6.4 与 §0–§5 脚本的差异（如实说明）

- 脚本要求"一遍过不拼接"，实际按**真实顺序分 5 段录制再拼接**（场景切换即切点）：B 段挂的号在 C 段队列里可见，C 段锁定的病历在 D 段看板里计为 1 份 —— 业务状态是连续的。
- 仓库**没有支付页**（全仓 grep 无"支付/微信/付款"），脚本里"勾选微信支付 → 立即支付"一段不存在，改为"确认挂号即生效"。
- 安卓模拟器不支持中文注入（`adb shell input text` 仅 ASCII）⇒ 分诊输入只在鸿蒙端演示。
- 管理端口令是临时口令、输入框为掩码，**未入镜**；`ai.key_ref` 只显示引用，未打开 `server/src/ai_builtin.cj` 的密钥行。
- 校时：44 句均按"页面出现即开口、页面切换前收口"对齐。

### 6.5 生产链路（可复现）

1. OBS 32.2.1 + obs-websocket，三个场景：`1-term`（窗口采集服务端控制台）、`2-harmony`（窗口采集鸿蒙模拟器，`cropRight` 去工具条）、`3-android`（窗口采集安卓模拟器）；统一 1920×1080@30、NVENC h264、mp4。鸿蒙模拟器须以软件渲染启动（`QT_ANGLE_PLATFORM=warp`、`QT_OPENGL=angle`），否则窗口采集全黑；录制期间不能最小化（WGC 采集不到最小化窗口）。
2. 交互由脚本驱动：`hdc` + `uitest uiInput`（含中文输入、`keyEvent Back` 收键盘）与 `adb shell input`，配合 layout dump 定位控件；每段录制的 `mark()` 写 `<clip>.marks.json` 时间锚点。
3. 后期：`edit2.py` 按锚点切片 → `videdit concat` → `videdit filter`（scale 1600×900 + pad 1920×1080 造底部字幕黑边 + tpad 补尾）→ `videdit voice`（TTS + 烧字幕）。

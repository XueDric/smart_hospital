## ★★ 一、开工前核实到的一个**关键事实**（改变了做法）

**DeepSeek 没有 embeddings 端点**。实测：

```
POST https://api.deepseek.com/embeddings      -> 404
POST https://api.deepseek.com/v1/embeddings   -> 404
```

⇒ 项目当前**拿不到 embedding 服务**。这直接决定了 P5 的做法 ——
而 brief §5.5 **其实已经预判了这种情况**：

> **降级**：向量模型不可用时回落关键词检索（与参考系统一致）

⇒ 所以 P5 建成**两层、可自证**：

| 层 | 依赖外部服务 | 状态 |
| --- | --- | --- |
| **关键词检索** | ❌ 不依赖 | ✅ **默认路径，永远可用，有真实测试** |
| **向量检索** | ✅ 需要 embedding 端点 | ✅ 已实现（余弦/序列化/排序都有测试）；接上端点即启用 |

★ **两层都必须如实标注 `source`**（`"keyword"` / `"vector"`）。
⚠ 绝不把关键词结果说成向量结果 —— 那是本仓反复点名的"看起来更好"的谎，
而且它会**掩盖"embedding 从没接上"**（第十份复查刚抓过一模一样的形态：
配置被校验/存库/回显，却没人消费）。

## 二、已交付 ✅

### 2.1 表（`schema.cj`，`KB_SCHEMA_DDL`，2 张）

| 表 | 作用 | 关键设计 |
| --- | --- | --- |
| `kb_doc` | 文档（**人维护的单位**） | `title` **唯一键**：知识库最容易出的问题是同一主题写了两份互相矛盾的文档，而检索会把两份都召回 ⇒ 模型看到矛盾内容，输出不可预测。让"重名"在写入那一刻失败。`enabled` 而非删除：停用后历史检索仍可解释 |
| `kb_chunk` | 切块（**检索的单位**） | `embedding` 存 **JSON 数组**（复刻参考系统做法）；**允许 NULL**（关键词路不需要向量 —— 这正是"零向量库"的关键）；唯一键 `(doc_id, seq)` ⇒ **重新切块时 upsert，不留旧块幽灵行** |

⚠ **为什么两张表而不是一张**：分层是因为**切块策略会变**（窗口/重叠），
而**改策略不该动文档**。合成一张表则每次调窗口都要重写文档行。

### 2.2 核心算法（`domain_kb.cj`，已编译通过）

| 函数 | 说明 |
| --- | --- |
| `kbChunk(body, window!, overlap!)` | 按**字符**切（不是字节）、相邻块**重叠**、尽量在**换行**处断开；★ **不丢内容**由 AC 钉住 |
| `kbCosine(a, b)` | 纯仓颉余弦；长度不等 ⇒ 0；零向量 ⇒ 0（**显式挡掉 `0/0` = NaN**，因为 NaN 比较恒 false ⇒ 排序不可预测） |
| `kbSqrt(x)` | 牛顿迭代（不为一函数引入新依赖） |
| `kbTokens(text)` | **汉字 2-gram** + 英数按词；去重 |
| `kbKeywordScore(q, content)` | **归一化**（命中词数 / 查询词数）—— 不归一化的话长块天然占优 |
| `kbSortHits(hits)` | 降序 + **稳定**（同分按 chunkId）—— 同分随机会让同一查询两次返回不同块 |
| `kbVectorToJson` / `kbVectorFromJson` | 向量 ↔ JSON；坏 JSON ⇒ **空数组**（一行坏数据不该让整个检索失败） |

**刻意的三个边界（都写在注释里）**：
1. `window <= overlap` 会让步进 ≤ 0 ⇒ **死循环** ⇒ 入口就夹住（不靠调用方自觉）。
2. `kbIsHan` 只覆盖 CJK 基本区（U+4E00..U+9FFF）⇒ 扩展区罕用字不参与检索，**已知边界**。
3. 本文件**不做任何网络调用** ⇒ 每个函数都能**纯逻辑测试**；"embedding 调不通"由 `ai_call.cj` 的降级覆盖。

## 四、本阶段的新增纪律（预备写进 README 踩坑表）

| # | 纪律 | 为什么 |
| --- | --- | --- |
| AI | ★★ **"降级路径"必须是可测的默认路径，不是备用方案** | brief §5.5 的降级是"向量不可用 ⇒ 关键词"。若把关键词做成"很少走的兜底"，它就**永远不会被测到** ⇒ 真需要它时才发现它坏了。⇒ 本项目把**关键词设为默认路径**（无外部依赖 ⇒ CI 永远能测），向量作为**需要配置才启用**的增强 |
| AJ | ★★ **两条路的分数不可混排时，就不要混排** | 关键词分是"覆盖比例"，向量分是"余弦"，量纲不同 ⇒ 混排等于**用不可比的数排序**。正确做法是**二选一**（由"有没有 embedding"决定），并如实标注 `source` |
| AK | **切块算法最容易错的不是"切得难看"，而是"悄悄丢内容"** | 丢内容在检索时表现为"某些问题永远查不到"，**极难从结果上发现** ⇒ 必须用"各块拼起来覆盖全文"这种**结构性断言**钉住，而不是抽样看几块 |

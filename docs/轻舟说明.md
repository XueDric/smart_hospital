# 轻舟（QingZhou）：我们自研的仓颉 Web 框架

> 一句话：**轻舟是本团队自研并开源的仓颉 Web 框架**（MIT）。本作品因此同时具备两层产出——**框架侧的设计与实现**，以及**跑在这个框架上的完整门诊业务闭环**。
> 本文只写"能核对"的东西：每条结论给出仓库内证据（`路径:行号`、提交哈希）。

## 一、轻舟是什么

- 仓颉（Cangjie）生态的 Koa 风格 Web 框架：洋葱中间件、Trie 路由、SSE/chunked 出站流式、静态托管（gzip / Range / ETag）、数据库抽象与参数化绑定、出站 HTTPS 客户端与重试退避。
- 以 MIT 许可证独立开源发布：`https://gitcode.com/BIT-FSSLab/QingZhou`，版权署名为本团队所在实验室（`server/third_party/qingzhou/LICENSE:1-3`）。
- 本仓库固定一份**源码快照**（`3d6c1a36…387b753`，v0.12.0 之后的 HEAD），构建不读取仓库外目录：快照就是上游代码本身，见 `server/third_party/qingzhou/PROVENANCE.md`。目的是**可复现构建**——任何人（含 CI）用同一份源码编出同一份 exe；快照与上游 `3d6c1a36` 的 `src/*.cj` 逐字节一致。

## 三、"框架设计 + 应用场景"的双层价值

| 层 | 我们做了什么 | 在哪 |
| --- | --- | --- |
| 框架层（设计/实现） | 路由与静态托管的错误体可注入、数据库抽象的断链自愈与探活、MySQL 驱动的参数化绑定正确性 | `server/third_party/qingzhou/src/{router,static,db,db_mysql}.cj` |
| 应用层（业务闭环） | 号源与挂号独立 MySQL 路径、就诊状态机、病历七段式 + 定稿锁定、AI 三态降级与校验层、三端客户端 | `server/src/`（38 个业务 `.cj`）、`feature-*/`、`android-patient/` |

这也是答辩时需要点明的一句话：**"我们写了一个国产 Web 框架，又在这个基座上把一个门诊闭环做完了。"**

## 四、一致性纪律（评审第 5 条要求的"别并存两套口径"）

1. **一个事实只写一处真值**：体积/哈希来自本页；断言数来自 `doc-counts.ps1` 的实测。
2. **历史文档不改口径而是标注**：评审原文、复验记录里保留当时数字，但顶部加"本文数字为当时值，现行口径见交付快照"的引用块（已在 `docs/评审反馈-2026-10-17.md`、`docs/REVERIFY-AND-FIXES-2026-10-17.md` 这么做）。
3. **重建即刷新**：任何交付物重建后 `check-snapshot.ps1 -Update` + `doc-counts.ps1 -Fix`，两个都绿再提交。
4. **CI 只验不改**：`.github/workflows/repo-hygiene.yml` 跑 `check-docs.ps1` 与 `check-snapshot.ps1`（默认模式），不让 CI 替你刷新快照。
5. **版本号单一来源**：`server/src/main.cj` 的 `SERVER_VERSION`；`/health`、分发包名、CHANGELOG 标题都从它对齐。

## 五、怎么用

```powershell
# 交付物重建后：刷新快照（会改写上面的机器校验块）
.\tools\check-snapshot.ps1 -Update

# 交付前：严格校验（快照与磁盘不一致就红）
.\tools\check-snapshot.ps1

# 断言数对账（会真跑 accept / triagetest，需要数据库）
.\server\tests\doc-counts.ps1
```

# 三人团队鸿蒙端分工方案

> **适用范围**：智慧医院智能导诊就诊系统 · **鸿蒙端（ArkTS + ArkUI）**开发
> **团队构成**：3 名鸿蒙开发，其中 1 人（C）兼界面设计
> **接口口径**：以 [`docs/FRONTEND-INTEGRATION.md`](FRONTEND-INTEGRATION.md) 为准；页面清单见 [`docs/前端开发梳理与页面清单.md`](前端开发梳理与页面清单.md)
> **进度跟踪**：见本文 [第六章 · 进度跟踪表](#六进度跟踪表)

---

## 一、项目背景速览

本项目服务端由**外部团队**负责，是一套基于 FastAPI + LangChain + ReAct Agent 的智慧医院智能导诊就诊系统。

- **现有前端**：Vue 3 + Element Plus（医疗青绿主题 `#00a9a7`），功能覆盖患者端、医生端、管理端。
- **鸿蒙端**：需从零用 **ArkTS + ArkUI 原生**重写 ⇒ **不能直接复用 Vue 的 UI 代码**，但**可以复用接口协议与业务逻辑设计**。

| 端 | 现有功能（Vue 3 参照） |
| --- | --- |
| 患者端 | 智能分诊、预问诊、预约挂号、我的就诊 |
| 医生端 | 门诊接诊、电子病历 |
| 管理端 | 基础数据、AI 能力中心、运营看板 |

## 四、协作机制

### 4.1 模块边界与接口约定

按「**依赖单向**：`app → feature → common-core`，**业务模块之间禁止互相 import**」的原则组织工程结构。

A 和 B 各自的功能模块通过 `common-core` 中的**路由和网络层**通信，**不直接互相依赖**。

### 4.2 接口对接节奏

| 时间 | 事项 |
| --- | --- |
| 第 1 周 | A 完成网络层封装，与外部服务端团队确认全部接口协议 |
| 第 2 周起 | A、B 并行开发，C 完成设计规范 + 公共组件初版 |
| 联调阶段 | 按模块独立联调：**A 负责患者端接口，B 负责医生端和管理端接口** |

### 4.3 设计交付节奏

C 的设计工作建议**前置**：

| 时间 | 事项 |
| --- | --- |
| 第 1 周 | 完成设计规范（色彩、字体、间距、组件基础样式） |
| 第 2 周 | 完成核心页面高保真设计稿 |
| 第 3 周起 | 边开发公共组件边迭代细节设计 |

### 4.4 可复用的现成资源

1. **华为开发者联盟**提供医疗健康类 HarmonyOS 模板，含健康数据可视化、预约挂号等场景的现成组件，可直接参考或复用，大幅减少从零设计的工作量。
2. **现有 Vue 3 前端**已完成交互设计和业务逻辑梳理 ⇒ 鸿蒙端可直接参照 Vue 端的页面结构与交互流程做 ArkTS 重写。**C 的设计工作更多是在视觉层做鸿蒙原生适配，而非从零开始设计交互。**

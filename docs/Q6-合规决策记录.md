# Q6 合规决策记录：模型出站与患者主诉

> **背景**：P2 立分诊时**刻意只做规则**，把「接真模型」挂起，理由写在
> `server/README.md` 与 `docs/P2-HANDOFF.md`：**brief §10 的 Q6 合规评估未决**。
> 现在真模型已经接通（`ai_call.cj` + `ai_triage.cj`），这条记录把 Q6 **落地**：
> 说清"到底把什么数据发出去了、默认状态是什么、谁负责批"。
>
> ⚠ 为什么必须写这一页（第十份复查指出）：接通出站 = **把患者主诉发给第三方**。
> 这是**合规决策**，不是工程细节；工程这边只负责把**事实与闸门**讲清楚，
> **批准与否不在工程侧**。

---

## 一、事实：到底有什么数据离开本院

| 出站内容 | 是否含患者标识 | 说明 |
| --- | --- | --- |
| 患者主诉原文（`chief_complaint`） | ❌ 不含 | 患者自己写的一句话，**可能含可识别信息**（如"我是 XX 单位的"） |
| 规则已判定的科室名 | ❌ 不含 | 机构信息 |
| 系统提示词（`AI_SYS_FALLBACK` 或 P3 的 `prompt.*` 模板） | ❌ 不含 | 静态文本 |
| **患者身份**（姓名/手机号/身份证/`patient_id`） | ✅ **从不出站** | 请求体里**没有**任何标识字段（见 `aiTriagePrompt()`） |
| **就诊记录 / 病历正文** | ✅ **从不出站** | 本阶段只发主诉，不发既往史/病历 |
| 密钥 | ✅ 只进 `Authorization` 头 | 且**不落库、不进日志**（P3 机制） |

**出站目标**：`ai.endpoint`（管理员配置，**必须 `https://`**，见 `aiRuntimeValidate`）。

---

## 二、默认状态：**关**

| 闸门 | 默认 | 位置 |
| --- | --- | --- |
| `ai.enabled` | **`0`（关）** | `AiSettingSpec(SET_AI_ENABLED, …, "0")` |
| `ai.endpoint` / `ai.model` / `ai.key_ref` | **空** | 同上 |
| ⇒ 净效果 | **未配置时 `aiCanCall()` 返回 false，`ai_call.cj` 一行出站代码都不会执行** | `ai_call.cj` 的 `aiCanCall()` |

⇒ **风险是"可被开启"，不是"已默认开启"**。⚠ 但这条**必须明确写下来**：
对一家医院，"可被开启"本身就要求有审批与留痕，不能靠"我们默认没开"。

---

## 三、闸门（工程侧已实现的机制，不是承诺）

1. **两道开关**：`ai.enabled`（总开关）+ 配置齐备性（endpoint/model/key_ref）。
   缺任一项 → 不出站，且 `ai_reason` **说清缺哪项**。
2. **失败必降级**：任何网络/解析失败 → `source=rules`（回退规则），
   **患者就医路径不因模型不可用而中断**。
3. **输出过安全层**：命中诊断/用药词 → **整条丢弃**（`aiSanitizeNote`）。
4. **模型改不了推荐**：`options`（科室/排班/号源）全部由规则 + 数据库决定，
   `aiEnhanceTriage` **只写** `aiNote`/`aiReason`（见 `ai_triage.cj` 文件头）。
5. **危急征象不调模型**：那条路径只该让患者尽快看到「立即就医」。
6. **可审计**：每次分诊的结论进 `triage_stat`（`source` 区分 `model`/`rules`/`model:invalid`），
   看板按 `source` 报**真实分布**（不含预问诊，已在响应里写明口径）。
   ⚠ **记录的是结论，不是主诉原文** —— `TriageStatRepo.record()` 的签名里**没有主诉参数**，
   "想记主诉"在类型层面做不到。

## 四、仍未做的（诚实边界，**不要读成已完成**）

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | **没有出站数据保留/删除协议** | 第三方是否留存、留多久、如何删除 —— 需与供应商签数据处理协议（DPA），**工程侧无法解决** |
| 2 | **没有患者知情/同意流程** | "主诉会被发送至第三方模型"是否需要在界面上告知或取得同意，属**产品 + 合规**决策 |
| 3 | **没有脱敏预处理** | 主诉是自由文本，患者可能自己写进可识别信息。当前**原样发送** ⚠ |
| 4 | **没有出站审计日志** | 有 `triage_stat` 的**计数**，但没有"哪次请求发了什么"的明细（⚠ 与"不留原文"是权衡关系，需决策） |
| 5 | **没有境外/境内部署约束** | 未限制 `ai.endpoint` 的域名/地域；真实落地通常要求**境内**或**私有部署** |
| 6 | **预问诊未接模型** | 采集槽位保持**确定性规则**（结构化数据由模型产出风险更高），故不发任何数据 |

## 五、谁批准

| 角色 | 职责 |
| --- | --- |
| **项目组 / 产品** | 决定是否开启、开给哪些功能、界面是否告知患者 |
| **合规 / 法务** | Q6 的**主体**：DPA、数据出境、知情同意、留存期限 |
| **运维** | 配置 `ai.*` 并把**真实密钥放进程环境**（`env:` 引用，不落库） |
| **工程（本仓）** | 只保证上面 §三 的闸门**真实生效**、§四 的边界**如实标注** |

> ⚠ **本页不代表 Q6 已获批准。** 它把"要批什么、谁来批、默认是什么"摆出来，
> 让这项决策**可以被做出并留痕**。在那之前，生产环境的 `ai.enabled` 应保持 `0`。

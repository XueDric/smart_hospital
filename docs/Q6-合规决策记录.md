# Q6 合规决策记录：模型出站与患者主诉

> **背景**：分诊最初**只做规则**，把「接真模型」挂起，原因是
> **brief §10 的 Q6 合规评估未决**。
> 现在真模型已经接通（`ai_call.cj` + `ai_triage.cj`），这条记录把 Q6 **落地**：
> 说清"到底把什么数据发出去了、默认状态是什么、谁负责批"。
>
> ⚠ 为什么必须写这一页（第十份复查指出）：接通出站 = **把患者主诉发给第三方**。
> 这是**合规决策**，不是工程细节；工程这边只负责把**事实与闸门**讲清楚，
> **批准与否不在工程侧**。

---

## 一、事实：到底有什么数据离开本院

| 出站内容 | 是否含患者标识 | 说明 |
| --- | --- | --- |
| 患者主诉原文（`chief_complaint`） | ❌ 不含 | 患者自己写的一句话，**可能含可识别信息**（如"我是 XX 单位的"） |
| 规则已判定的科室名 | ❌ 不含 | 机构信息 |
| 系统提示词（`AI_SYS_FALLBACK` 或 P3 的 `prompt.*` 模板） | ❌ 不含 | 静态文本 |
| **患者身份**（姓名/手机号/身份证/`patient_id`） | ✅ **从不出站** | 请求体里**没有**任何标识字段（见 `aiTriagePrompt()`） |
| **就诊记录 / 病历正文** | ✅ **从不出站** | 本阶段只发主诉，不发既往史/病历 |
| ★ **知识库检索命中的片段**（P5 新增） | ❌ 不含患者标识 | ⚠ **这是 P5 引入的新出站内容**：片段来自 `kb_doc.body`（**本院人员维护**），会随 Prompt 发给第三方。⇒ **知识库里不得放患者个人信息** |
| 密钥 | ✅ 只进 `Authorization` 头 | 且**不落库、不进日志**（P3 机制） |

**出站目标**：`ai.endpoint`（管理员配置，**必须 `https://`**，见 `aiRuntimeValidate`）。

## 二、默认状态：**关**（原始决策；**已被 §2.1 的 2026-10-17 口径变更覆盖**，本节保留为决策痕迹）

| 闸门 | 默认 | 位置 |
| --- | --- | --- |
| `ai.enabled` | **`0`（关）** | `AiSettingSpec(SET_AI_ENABLED, …, "0")` |
| `ai.endpoint` / `ai.model` / `ai.key_ref` | **空** | 同上 |
| ⇒ 净效果 | **未配置时 `aiCanCall()` 返回 false，`ai_call.cj` 一行出站代码都不会执行** | `ai_call.cj` 的 `aiCanCall()` |

⇒ **风险是"可被开启"，不是"已默认开启"**。⚠ 但这条**必须明确写下来**：
对一家医院，"可被开启"本身就要求有审批与留痕，不能靠"我们默认没开"。

### 2.1 ⚠ 2026-10-17 口径变更：演示环境默认**开**

外部意见「默认一次模型调用都不调，无法验证智能部分」，故 2026-10-17 起把默认值改为：

| 闸门 | 新默认 | 位置 |
| --- | --- | --- |
| `ai.enabled` | **`1`（开）** | `server/src/ai_settings.cj` 的 `AiSettingSpec(SET_AI_ENABLED, …, "1")` |
| `ai.endpoint` | `https://api.deepseek.com/chat/completions` | 同上（`AI_BUILTIN_DEFAULT_ENDPOINT`）|
| `ai.model` | `deepseek-chat` | 同上（`AI_BUILTIN_DEFAULT_MODEL`）|
| `ai.key_ref` | **`builtin:demo`**（仍是**引用**，库里无裸密钥） | 同上（`AI_BUILTIN_DEFAULT_KEY_REF`）|

**这不是"把合规换成分数"**，边界写死在这里：

1. **只对演示/开发生效**：`builtin:demo` 是内置演示密钥，**随源码与二进制分发**（`server/src/ai_builtin.cj` 头部有红字警告）。
2. **★ 有效期是代码行为，不是承诺**（2026-10-18 增）：`AI_BUILTIN_DEMO_VALID_UNTIL = 2026-12-31`。
   到期后 `aiResolveKey()` **拒绝**这把 key，`aiKeyRefProblem()` 回「已于 <日期> 失效 …… 请换用
   `env:`/`file:`」，分诊自动降级到规则 —— 伤害窗口从"永久"压到"评审/演示窗口"。
   这条由 `accept` 的 ⑧ 段 8 条纯逻辑断言守着（`acceptance_ai_call.cj`），不是文档口头约定。
   **实测证据（2026-10-18）**：把常量临时改成 `2020-01-01` 重编后启动，服务端打印
   `⚠ 但**密钥引用解析不到**（builtin）：调用会失败并回落规则兜底`；`POST /api/v1/admin/ai/models/848/test`
   返回 `ok=false, http_status=0, reason="内置演示密钥已于 2020-01-01 失效（…）—— 请换用自己的密钥…"`；
   把日期改回 `2026-12-31` 重编后同一探测恢复 `ok=true, http_status=200, 899 ms`。
   ⚠ 有效期**防不住**窗口期内有人拿走 key 去用：所以余额要小，窗口结束去控制台**吊销**
   （改日期只防"代码继续用它"，不防已经流出去的副本）。
3. **改用评委自己的密钥只需一条命令**：`.\tools\set-ai-key.ps1 -ApiKey sk-… -AdminPw <口令>`
   （写 `server\ai-key.txt`，已 gitignore；把 `ai.key_ref` 改成 `file:<绝对路径>`；再调一次
   模型自检回显 `ok=true`）。这条路径同样**不落库密钥本体**。
4. **生产上线前必做三件事**：① 把 `ai.key_ref` 换成 `env:…` 或 `file:…` 并**轮换**该密钥；② 由 Q6 审批结论决定 `ai.enabled` 是否置回 `0`；③ 按 §四 补齐 DPA / 知情同意 / 出站地域约束。
5. **机制不变**：仍只存引用、仍机制性拒绝裸密钥、仍失败降级到规则、仍过安全层、`options` 仍由规则+库决定。
6. **可自证**：`server/tests/ai-live-check.ps1`（默认 **26 项**；带 `-ApiKey` 走 28 项，多出两条"用户自备密钥也能调通"的断言）会断言响应里搜不到 `sk-…` 指纹，且 `ai.key_ref` 显示为 `builtin:demo` 而非密钥本体。

## 三、闸门（工程侧已实现的机制，不是承诺）

1. **两道开关**：`ai.enabled`（总开关）+ 配置齐备性（endpoint/model/key_ref）。
   缺任一项 → 不出站，且 `ai_reason` **说清缺哪项**。
2. **失败必降级**：任何网络/解析失败 → `source=rules`（回退规则），
   **患者就医路径不因模型不可用而中断**。
3. **输出过安全层**：命中诊断/用药词 → **整条丢弃**（`aiSanitizeNote`）。
4. **模型改不了推荐**：`options`（科室/排班/号源）全部由规则 + 数据库决定，
   `aiEnhanceTriage` **只写** `aiNote`/`aiReason`（见 `ai_triage.cj` 文件头）。
5. **危急征象不调模型**：那条路径只该让患者尽快看到「立即就医」。
6. ★★ **P5 新增闸门：知识库写入时机制性拒绝明显的个人信息形态**
   （18 位数字 / **17 位 + X** / 11 位手机号）；⚠ **姓名识别做不到**（中文姓名无法可靠区分于普通词）
   ⇒ 归类为「仍需人工把关」，见 §四。
7. **可审计**：每次分诊的结论进 `triage_stat`（`source` 区分 `model`/`rules`/`model:invalid`），
   看板按 `source` 报**真实分布**（不含预问诊，已在响应里写明口径）。
   ⚠ **记录的是结论，不是主诉原文** —— `TriageStatRepo.record()` 的签名里**没有主诉参数**，
   "想记主诉"在类型层面做不到。

## 四、仍未做的（诚实边界，**不要读成已完成**）

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | **没有出站数据保留/删除协议** | 第三方是否留存、留多久、如何删除 —— 需与供应商签数据处理协议（DPA），**工程侧无法解决** |
| 2 | **没有患者知情/同意流程** | "主诉会被发送至第三方模型"是否需要在界面上告知或取得同意，属**产品 + 合规**决策 |
| 3 | **没有脱敏预处理** | 主诉是自由文本，患者可能自己写进可识别信息。当前**原样发送** ⚠。⚠ 知识库片段同理（P5）—— 写入时的形态检查只挡"明显形态"，**姓名等仍靠人工** |
| 4 | **没有出站审计日志** | 有 `triage_stat` 的**计数**，但没有"哪次请求发了什么"的明细（⚠ 与"不留原文"是权衡关系，需决策） |
| 5 | **没有境外/境内部署约束** | 未限制 `ai.endpoint` 的域名/地域；真实落地通常要求**境内**或**私有部署** |
| 6 | **预问诊未接模型** | 采集槽位保持**确定性规则**（结构化数据由模型产出风险更高），故不发任何数据 |

## 五、谁批准

| 角色 | 职责 |
| --- | --- |
| **项目组 / 产品** | 决定是否开启、开给哪些功能、界面是否告知患者 |

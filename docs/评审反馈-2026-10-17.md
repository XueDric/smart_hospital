### 3.1 系统完整性与运行稳定性：18 / 25

#### 加分依据（可复现）

- **81 个 REST 端点、17 张表、37 个业务 `.cj`**。端点按 `r\.(get|post|put|delete)\("/api/` 计数：http_app 38 + http_p4 18 + http_base 12 + http_kb 7 + http_notice 6 = 81；建表按 `CREATE TABLE IF NOT EXISTS` 计数：schema.cj 行 261/284/299/312/348/430/495/537/556/598/615/665/691/730/757/786/842 = 17。

- **在线实测三条业务分支行为正确**：
  - 危急征象：`{"chief_complaint":"最近胸口痛，还出汗，有点喘不上气"}` → `red_flag:true, source:"rules", ai_reason:"危急征象：优先让患者立刻看到处置建议，不进模型"`。
  - 科室未开诊：`胃疼` → `reason_code:"ALTERNATIVES"`，患者文案「本院暂未开诊「消化内科」，建议咨询导诊台确认科室。以下这些科室当前有号……」+ 备选有号科室。
  - 无法判断：→ `NEED_CLARIFY` + 引导补充信息（**没有崩、没有空白页**）。
- **错误契约统一**：未登录调 `/api/v1/triage` → 401；缺必填字段 → `{"ok":false,"error":{"code":"VALIDATION_FAILED","message":"缺少必填字段 chief_complaint"}}`，并带 `x-request-id` 与 CORS 头。

### 3.3 智能技术应用深度：10.5 / 20（最重扣分项）

20 分考的是"智能技术用得多深"。实测结论：**这是一个规则引擎，模型只是可选的文案润色器，且默认关闭。**

#### 链路真相

`POST /api/v1/triage`（`server/src/http_app.cj:2146`）→ `triageComplaint()`（`server/src/triage.cj:459`）：
- 危急征象 `:466-477` → 空主诉 `:480` → 14 科室 / 123 关键词 `:488` → 真实号源 SQL `:497` → 备选科室 `:511` → 兜底拒答 `:579`
- → 知识库同义词扩充 `triageRagHits()`（`http_app.cj:1038-1048`）
- → `aiEnhanceTriage()`（`server/src/ai_triage.cj:163`）→ `aiCallChatBudget/aiCallChatRaw`（`ai_call.cj:296/329`）→ `aiSanitizeNote`（`ai_triage.cj:262-288`）
- 全程**只写 `aiNote` / `source`**：`TriageOption` 只在 `triage.cj:425` 构造，`v.options` 只在 `:499/:534` 赋值，**无任何代码把模型文本映射成科室**。

> "模型不能改结论"是**安全优先的正确取舍**，值得给分；但它同时意味着 AI 语义贡献只剩患者提示语一句话。

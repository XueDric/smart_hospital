## 六、怎么在干净机器上复现（四步）

```powershell
# 1) 起便携数据库（首次会自动初始化 data 目录）
cd server
.\devdb.ps1 start -Port 3417

# 2) 建表 + 管理员（口令只打印一次，走 stderr）
.\build\hospital-server.exe create-db "mysql://hospital:hospital_dev_2026@127.0.0.1:3417/hospital_test" -AdminLogin admin
.\build\hospital-server.exe create-admin "mysql://hospital:hospital_dev_2026@127.0.0.1:3417/hospital_test" admin

# 3) 动嘴的部分（三件套 + 断言套）
.\build\hospital-server.exe selftest
.\build\hospital-server.exe triagetest
.\build\hospital-server.exe accept "mysql://hospital:hospital_dev_2026@127.0.0.1:3417/hospital_test"

# 4) 全量门禁（18 项，含真实 HTTP + 契约 + 文档对账）
.\tests\final-verify.ps1 -Dsn "mysql://hospital:hospital_dev_2026@127.0.0.1:3417/hospital_test"
```

**三个容易踩的坑**（都实测踩过）：

1. `accept` 与任何 e2e 脚本**不能并发**：`accept` 的 `hResetAll` 会清业务表。
2. `create-admin` 每次都会**重置**管理员口令 —— 老脚本里存的旧口令会变成 HTTP 401。
3. `final-verify` 的子脚本各自有 `-Dsn`（默认 3317）；DSN 不是 3317 时必须显式传（本仓库已改成
   从 `-Dsn` 派生并传给每个子脚本）。

## 七、这份文档自己怎么更新

数字是**跑出来的**，改了代码就该重跑再改这份文档：

```powershell
# accept 的原文与计数
.\server\build\hospital-server.exe accept <DSN> | Tee-Object .build-tools\accept.log

# 18 项门禁的原文
.\server\tests\final-verify.ps1 -Dsn <DSN> | Tee-Object .build-tools\final-verify.log

# 文档里的数字与实测是否一致（不一致就 exit 1）
.\server\tests\doc-counts.ps1 -Dsn <DSN>
```

`tools/check-docs.ps1` 会校验本文件里**没有失效的相对链接**；`doc-counts.ps1` 会对账
`README.md` / `docs/PROJECT-OVERVIEW.md` 等处写的 `821`、`150` 等数字 —— 所以"文档撒谎"在这个仓库里
是会被 CI 拦下的（不是在评审时才被发现）。

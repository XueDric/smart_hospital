### BUG-11 医生端「一键预填」是假复制（2026-10-21 复验发现并修复）

- **现象**：点「一键预填」只弹一句"已用预问诊单预填"，七个输入框仍是空的，医生还得手打。
- **根因**（三处叠加，缺一处都修不好）：① `server/src/domain_emr.cj` 的 `saveDraft` 把预填包在 `if (!exists)` 里，病历行存在后永不发生；② 预填判据是 `if (!patch.contains(k))`，而客户端 `EmrEditPage.ets` 的 `valuesMap()` 七段全量发送（空串也算），首次点击也进不了一段；③ 预填之后才套 `patch`，补上的值被空串当场擦掉。附带：`exists` 分支的 `UPDATE medical_record` 不含 `previsit_ref`，来源记不下来。
- **处置**：改成"先落 patch、再只补空段、最后写 `previsit_ref`"，`UPDATE` 补上 `previsit_ref` 列；客户端两处文案改为"补齐空段（医生已写的内容不覆盖）"。`accept` 794 → 801（⑧⑨⑩ 七条断言覆盖客户端真实请求形状 / 已有病历 / 医生已写不被覆盖）。
- **实证**：模拟器实跑 + `medical_record`（appointment 970001）落库核对，截图 `release/harmony/screenshots/17-doctor-emr-prefilled.jpeg`。
## 三、已修 7 条

### 3.1 挂号后余量不刷新（BUG-1）

`BookingPage.loadSchedules()` 增 `keepMessage: boolean = false` 参数：为真时不清 `successMessage`（否则刚弹出的「挂号成功」会被刷新清掉），挂号成功路径末尾补 `await this.loadSchedules(true)`。

实跑（鸿蒙患者端）：`挂号成功：2026-10-18 上午，序号 1`，同页卡片立刻由「余 3」变「余 2」、按钮变「已预约该号源」。

### 3.2 登录响应 patient_id 不分角色（BUG-4）

服务端 `server/src/http_app.cj` 登录分支里改为按角色算：患者给 `ref_id`，其它角色给 `0`。与 `/auth/me` 的 `patient_id` / `doctor_id` 口径对齐。

> 客户端此前恰好只对患者用 `patient_id`，所以没露出问题——属于"再接入一个端就会踩"的隐患。

### 3.3 未来日期的号可以接诊（BUG-5）

`VisitQueuePage` 新增 `isToday()` / `blockNotToday()`，`arrive` / `waiting` / `start` 三个动作入口各加一道守卫。实跑：点 2026-12-24 那张的「到院登记」→ 红条 `该号的就诊日是 2026-12-24，不是今天，不能到院登记/接诊`，库里仍是 `booked`、`arrived_at=0`；点今天那张 → 正常 `arrived`。

截图：[13-doctor-queue-gated.jpeg](../release/harmony/screenshots/13-doctor-queue-gated.jpeg)

### 3.4 队列「今日」名不副实（BUG-6）

分段由 `今日 / 上午 / 下午` 改为 `全部 / 上午 / 下午`，副标题写明「按状态展示接诊顺序（含历史与未来日期）」。

### 3.5 看板假指标（BUG-7）

「分诊命中率 0%」改为「分诊调用 N」，数据来自服务端 `triage.total_calls`（真实计数）。`AdminModels` 删 `triageHitPct`，改为 `triageCalls / triageRedFlagCalls / trendDays`。

理由写在代码注释里：`triage_stat` 表没有 `patient_id` / `appointment_id`，**命中率根本算不出来**；与其显示一个恒为 0 的百分比，不如显示能自证的调用次数。

### 3.6 趋势含未来日期（BUG-8）

`server/src/dashboard.cj` 的趋势 SQL 由 `WHERE visit_date >= ?` 改为 `WHERE visit_date >= ? AND visit_date <= ?`（上界 = 今天），标题改为 `近 ${trendDays} 日挂号趋势`。

实跑：`trend = [{"label":"2026-10-18","count":1}]`，未来柱子消失。

截图：[14-admin-dashboard-triage-calls.jpeg](../release/harmony/screenshots/14-admin-dashboard-triage-calls.jpeg)

### 3.7 挂号列表忽略号源自带名字（BUG-10）

`PatientModels.Schedule` 补 `departmentName / doctorName / doctorTitle`，`PatientRepository.parseSchedule` 读服务端本就返回的 `department_name / doctor_name / doctor_title`，卡片优先用号源自带名字。

实跑：从「常用服务 → 预约挂号」（**不带路由参数**）进入，卡片显示 `内科 / 张医生 · 主任医师 / 2026-10-18 上午 / 余 3`。

## 七、工具坑（会误导判断的几条）

1. **`uitest uiInput inputText` 是追加不是替换**：拿它改日期会把 `2026-10-18` 拼成 `2026-10-182026-12-24`。清空要用 `input keyevent 123`（MOVE_END）+ 多次 `keyevent 67`（DEL）或先重进页面。
2. **输入法候选栏会被误读成界面元素**：输入 `2026-10-18` 时键盘顶部显示 `-180046`，那是输入法自己的算式候选，不是应用渲染；应用同时给的红条 `work_date 格式应为 YYYY-MM-DD` 才是真反馈。
3. **`hdc install -r` 覆盖安装后首次启动偶发 `Failed to load Index: {"code":1300002}`**：再启动一次即正常（两次实测），属安装-重启竞态，不是应用缺陷。
4. **`uitest uiInput keyEvent Back` 会退到桌面**，收键盘要用 `uinput -K -d 2 -u 2`。
5. **`uitest uiInput inputText` 会往文本末尾多写一个 `%`**：入库 `medical_record` 的 `chief_complaint` / `diagnosis` 尾部有 `%` 都是这么来的，属自动化瑕疵，不是应用 bug（已用 `TRIM(TRAILING '%')` 清理）。
6. **`-screenshotPath` 不生效**：`Emulator.exe -instance <name> -screenshot` 只存到 `C:/Users/ASUS/Pictures`；稳定做法是 `hdc shell snapshot_display -f /data/local/tmp/x.jpeg` + `hdc file recv`。

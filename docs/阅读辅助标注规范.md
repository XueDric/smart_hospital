# 阅读辅助内容标注规范

> **适用工程**：`frontend-interactive/`（含 `canvas.html`、`运行说明.html`）
> **目的**：把「只写给读者看、不承担业务功能、不应随生产构建部署」的文字显式标出来，让它们**可检索、可清点、可剥离**。
> **校验工具**：`node tools/reading-aid.mjs check`（等价 `npm run check:reading-aid`）

---

## 1. 判定标准：什么样的内容算「阅读辅助」

一条文字同时满足下面两条，才打标注：

| 条件 | 说明 |
| --- | --- |
| **① 面向读者** | 它的存在是为了让人**看懂**某个东西——解释设计依据、引用文档、说明怎么操作、声明这是演示 |
| **② 不承担业务** | 删掉它，页面的**业务流程与状态机不受影响**；它不是用户完成就诊闭环所必需的信息 |

**判定的试金石**：把这段文字整段删掉，如果「患者还是能完成分诊→挂号→取消」这条闭环，那它就是阅读辅助。

**反例（不要标注）**：

- 按钮文案、表单标签、表头、状态徽标（`已挂号` / `草稿` / `已锁定`）—— 这是操作必需的功能性文案
- 错误提示与校验反馈（`请填写科室名称、编码和位置。`、`SLOT_GONE：号源已约满`）—— 这是功能的一部分
- 业务代码中的注释 —— 注释不进入产物，见 §5

---

## 2. 四种类型

| 类型 | 含义 | 典型内容 |
| --- | --- | --- |
| `讲解` | 向读者解释实现、方案或概念 | FrameworkGuide 全部卡片、`descriptions` 页面说明、canvas 帧的 `desc` |
| `依据` | 文档出处、章节引用、契约摘要 | `evidence` 映射、属性面板的「文档依据」、页面底部 `fg-cite` |
| `演示` | 声明「这是虚构演示」的免责与标注 | 「本地演示」「虚构数据，不作为诊断」「演示预约已确认」 |
| `指引` | 告诉人怎么操作、怎么运行 | canvas 的操作提示、运行说明.html、构建命令说明 |

---

## 3. 四种标注形式

### 3.1 块级标记（包裹一段可整体剥离的内容）

```js
/* @reading-aid:begin 依据 —— 页面文档依据映射，仅用于向读者交代出处，不参与任何业务判断 */
export const evidence = { /* … */ };
/* @reading-aid:end */
```

```html
<!-- @reading-aid:begin 指引 —— 画布操作提示，纯阅读辅助，生产环境应移除 -->
<div class="hint">…</div>
<!-- @reading-aid:end -->
```

规则：

- `begin` 行必须写类型（`讲解` / `依据` / `演示` / `指引`）与一句说明
- `end` 行只写 `@reading-aid:end`
- **必须成对**，且不能嵌套交叉（工具按栈校验）
- 块内可以有多行，也可以只有一行

### 3.2 元素属性（行内文案，无法成块包裹时）

密集单行模板里，用属性标注**承载该文案的元素**：

```html
<div class="aside-meta" data-reading-aid="演示">
  <p>当前为独立交互演示。所有医生、号源和就诊数据均为虚构示例。</p>
</div>
```

属性值只能是 §2 的四种类型之一。属性可被工具统计，也可在浏览器里通过
`document.querySelectorAll('[data-reading-aid]')` 直接清点。

### 3.3 整文件横幅（整个文件都是阅读辅助）

放在文件最前面（前 10 行内）：

```html
<!-- @reading-aid:file 指引 —— 本文件整体为运行说明，不参与任何构建与运行 -->
```

```js
/* @reading-aid:file 讲解 —— 本组件整体为框架说明页，删除后不影响其余页面 */
```

### 3.4 行内标记（阅读辅助文字嵌在功能性代码行里）

密集的数据文件（例如虚构种子数据、toast 文案）里，免责措辞往往**嵌在一行功能代码中间**，既无法成块包裹，也不能整行删除。此时在**行尾**加行内标记：

```js
  records: { 2002: { sections: { diagnosis: '示例诊断 · 非医疗意见' } } },  // @reading-aid:演示 —— 免责后缀
  notify('演示挂号成功 · 已扣减 1 个号源');                                  // @reading-aid:演示 —— 免责措辞，功能反馈本身须保留
```

行内标记**只用于清点，不参与自动剥离**——因为整行包含功能代码，删行会破坏程序。剥离这类内容必须人工改写。

---

## 3.5 四种形式的对照

| 形式 | 写法 | 可自动剥离 | 适用场景 |
| --- | --- | --- | --- |
| 块级 | `@reading-aid:begin 类型 —— 说明` … `@reading-aid:end` | ✅ | 独立成段、可整体删除的阅读辅助 |
| 整文件 | `@reading-aid:file 类型 —— 说明` | ✅（整文件删除） | 整个文件都是阅读辅助 |
| 元素属性 | `data-reading-aid="类型"` | ✅（移除属性） | 单个 DOM 元素承载的文案 |
| 行内 | 行尾 `// @reading-aid:类型 —— 说明` | ❌ 需人工 | 嵌在功能代码行里的免责措辞 |

## 4. 使用方式

```bash
node tools/reading-aid.mjs check        # 校验配对与取值，失败返回非零退出码
node tools/reading-aid.mjs list         # 按文件列出全部标注
node tools/reading-aid.mjs manifest     # 重新生成 docs/阅读辅助内容清单.md
node tools/reading-aid.mjs strip <in> <out>   # 剥离块级标注，输出生产副本（见下）
```

### `strip` 的边界（重要）

`strip` 只处理 **`.html` / `.js` / `.css` / `.mjs`**，做法是删掉 `begin`–`end` 之间的内容、移除
`data-reading-aid` 属性。它**不处理 `.vue`**，因为 Vue SFC 里删掉模板节点会改变渲染结构；
也**不处理行内标记**，因为整行含功能代码（见 §3.4）。

因此对 Vue 工程，剥离靠的是「删文件 + 摘路由」这类人工动作，`strip` 只作为 HTML/JS 的辅助手段。
**无论用哪种方式，剥离后必须重新跑一遍 `npm test` 与 `npm run test:canvas`。**

## 5. 不在标注范围内的内容

下面这些**不进入产物**，因此不适用本规范，仅在清单里作为背景记录：

| 类别 | 位置 | 原因 |
| --- | --- | --- |
| 开发工具脚本 | `tools/*.mjs`、`tests/*.mjs`、`start-preview.cmd` | 只在开发机执行，不打包进 `dist/` |
| 工程说明文档 | `运行说明.html` 之外的 `*.md` | 不进入构建产物（`运行说明.html` 例外，它会被一起分发，故已标注） |
| 源码注释 | 各处 `//` 与 `/* */` 注释 | 编译/打包时被移除，不产生运行时效果 |
| 构建脚本锚点 | `canvas.html` 的 `@app-url` | 构建期占位符，属于工具约定，不是阅读辅助 |

---

## 6. 维护约定

1. **新增阅读辅助内容必须同时加标注**，否则 `check` 不报错但清单会遗漏——清单由 `manifest` 生成，人工复核。
2. **不要把功能性文案标成阅读辅助**。标注失真的代价是：生产剥离时会删掉用户真正需要的文字。
3. 判定有疑问时，用 §1 的试金石：删掉它，业务闭环还成立吗？

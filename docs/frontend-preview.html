01项目与前端边界

本仓库只有服务端（server/，仓颉 + 轻舟，自包含）；客户端为留白预留，由客户端同学另行开发。前端只消费后端 HTTP 契约，契约的唯一口径是 docs/FRONTEND-INTEGRATION.md。

前后端划分

侧现状边界
后端P0–P5 完成55+ REST；三端权限由单一函数 can(role, action) 强制
前端待实现只消费 HTTP 契约；不得出现患者无权调用的 /admin/**、/doctor/**
依据：《前端开发梳理与页面清单》§4；《FRONTEND-INTEGRATION》§5–§6

契约边界的 5 条关键约定

前缀业务接口全部 /api/v1；唯一例外 GET /health（根路径、不鉴权、不走信封）
成功信封{"ok":true,"data":{…}}（200/201）
失败信封{"ok":false,"error":{code,message,fields?}}
平铺失败还有两种无 ok 字段的框架层形状（非法 JSON / 路由不匹配）
传输release 必须 HTTPS；服务端 TLS 绝不静默降级

02技术栈

前端为「鸿蒙患者端（待建）」+「管理端（另立一期）」两块；下方同时列出已就绪的服务端与作为设计参照的既有 Vue 3 工程。

层技术备注 / 设计意图
客户端（待建）ArkTS + ArkUI 原生（HarmonyOS）从零重写，不复用 Vue UI 代码，但复用接口协议与业务逻辑设计
状态管理ArkTS 状态管理 V2@Local / @Param / @Event / @Provider / @Consumer，避免 V1/V2 混用
路由统一路由注册表（common-core 中的 Router）各 feature 模块向公共层注册页面，业务模块之间禁止互相 import
网络层统一 HTTP 客户端 + Bearer Token 注入 + SSE 流式解析SSE 仅用于预问诊打字机；挂号/AI 在线直连
持久化偏好存储 / 文件存储登录态只存 token + expires_at + role + ref_id，绝不存口令
服务端（已就绪）仓颉 1.2.0 + 轻舟 v0.12.0单进程、单 package；直接 SQL + 事务；MySQL/MariaDB 11.4
鉴权不透明令牌（32B → 64 hex）+ PBKDF2-HMAC-SHA256 100k不是 JWT，客户端不得解析；30 天 TTL + 服务端滑动续期，无 refresh 接口
管理端（另立一期）技术栈待定服务端已提供看板 / 基础数据 / AI 中心 / 知识库接口；参照 qingzhou/admin-web（Vue 3 + Vite）
参考系统（设计参照）Vue 3 + Vue Router + Vite + Element Plus（主题 #00a9a7）已完成的交互设计与业务逻辑梳理，鸿蒙端参照其页面结构与交互流程
依据：《前端开发梳理与页面清单》§3；《分工.md》§3.3 / §4.4

关键交互（对应左侧圆点）
  • ①错误提示条：401 AUTH_BAD_CREDENTIALS 显示服务端 message；429 时改为 读 retry-after 做倒计时并禁用登录按钮。

用途

多轮对话采集 6 个槽位（chief / duration / severity / associated / history / allergy），SSE 流式打字机；完成后生成预问诊单，可预填医生端病历。

关键交互（对应左侧圆点）
  • ①进度指示：用 filled / total_slots；form 仅在 complete 后出现，未完成时只给进度，不下发半成品表单。
  • ②流式气泡：SSE 四条硬性要求 —— 严格按 \n\n 分帧、整段 UTF-8 解码、meta 帧先取 session_id 并持久化复用、未收 done 帧视为失败并设超时。帧内业务对象在 内层 data（外层是 {event,data}）。
  • ③输入 / 发送：空串 = 跳过，不提交（不落库、不推进 turn）；给流设超时，连接关闭不等于完成。
  • ④「无」快捷项：「无」是有效阴性答案，与「没答」语义不同，必须提供快捷项，不要用空串代替。

设计意图

进页先 GET /previsit/:id（404 才开新流）—— 反复开新流会挤掉最旧的未完成会话（上限 5 个未完成 / 30 分钟闲置回收）。对话文本可流式，但业务值（answer）刻意非流式：流错了对话只是看到半句，流错了业务值是状态污染。

!关键交互红线

这三条是「写错了就是安全事故」的约定，必须在编码前对齐。

① 分诊 red_flag

red_flag=true 时 options 必空 ⇒ 只引导急诊/人工，绝不展示或自拼号源。服务端不返回命中的关键词，前端不得复述。

② 挂号 client_token 幂等

点一次生成一次、重试复用同一个值、换号源换新 token。409 SLOT_GONE → 刷新列表，不重试。

③ 在线直连，不进离线队列

挂号与 AI 调用必须在线直连 + 强一致确认；退号成功必须看 data.status === 'cancelled'。

依据：《前端开发梳理与页面清单》§10 结论 3；《FRONTEND-INTEGRATION》§8 / §10.2 / §10.3

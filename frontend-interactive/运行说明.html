智慧医院 · 独立交互工程

Vue 3 + Vite / HTML、CSS、JavaScript / 浅色青绿主题 / 桌面与移动自适应

最简单的运行方式：双击 dist/index.html。所有样式、脚本和图标已经内联，不需要网络、安装依赖或启动后端。

1. 运行与开发

  • 直接体验：打开 dist/index.html；在浏览器中点击侧栏患者端、医生端、管理端切换演示视角。
  • 本地 HTTP 预览：双击工程内 start-preview.cmd，浏览器打开 http://127.0.0.1:5178；需要 Node.js，关闭终端即停止服务。
  • 继续开发：在本目录终端执行以下命令，建议 Node.js 22。
npm install
npm run dev        # http://127.0.0.1:5178，Vue 热更新
npm run build      # 生成 dist/index.html，内联资源
npm run preview    # 只绑定 127.0.0.1:5178
npm test           # 浏览器交互回归

本机开发依赖已安装到隔离运行时目录，工程脚本会优先读取本项目依赖，找不到时读取隔离目录。下载源码后可以正常 npm install，无需使用本机的绝对路径。若测试机器没有 Chrome，请先执行 npx playwright install chromium，或设置 CHROME_PATH 指向现有 Chrome。测试结果和截图放到相邻 outputs/。PORT 环境变量可调整静态预览端口。

2. 演示路径

  1. 患者端：选择“咳嗽、发热” → 开始智能分诊 → 去挂号 → 预约确认 → 我的预约 → 取消预约。取消成功会归还演示号源。
  2. 危急状态：在分诊右侧点击“体验危急征象提醒”。出现强提醒，不展示普通门诊推荐。
  3. 预问诊：每项输入演示答案或点击“无”，完成 6 项；正文显示打字机效果，空答案不会推进。
  4. 医生端：开始接诊 → 首次预问诊预填 → 填写诊断与处理意见 → 保存草稿 → 提交锁定 → 返回队列 → 完成就诊。
  5. 管理端：科室、医生、排班、账号、知识库支持对应创建和表单反馈；科室或医生有引用不可删。AI 支持配置校验、模板编辑和工具开关。
  6. 设计依据：点击各页右上角“设计依据”，或侧栏“框架与文档依据”，查看技术栈、目录、组件、视觉、构建、文档出处。
  7. 登录页面：演示登录名 demo.patient，口令 Demo123!。错误连续 3 次显示 10 秒禁用倒计时。口令不保存。

4. 数据与真实系统边界

这是可交互的前端演示，不是医院生产系统，也不是鸿蒙 HAP 工程。患者 9 页（记录列表与详情合并路由）、医生 2 页、管理 7 页均保留核心内容。所有医院、医生、预约和病历为虚构数据；不连接现有后端、不出站调用模型、不发送患者描述。所有变更仅保存在内存，刷新恢复初始值。端切换为演示工具，不代替真实鉴权。不要输入真实医疗信息、真实口令或真实 API 密钥。

真实接入需对接 /api/v1 契约、不透明 Bearer 令牌、统一失败解析、真实 SSE、幂等挂号、在线号源和 MySQL 状态。客户端不得借用管理员接口获取科室/医生列表，不能把本地确认作为真实挂号成功。本工程保留这些依据，但没有宣称已完成真实服务端联调。

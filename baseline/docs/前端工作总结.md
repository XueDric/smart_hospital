## 二、各模块产出

### A 彭翌菲 — 基建 + 认证（阻塞 B/C/D 的地基）

- `HttpClient` 统一请求层：自动加 `Authorization: Bearer token`、401 跳登录、403 提示无权限、错误码逐字段映射、网络异常 try-catch 防崩
- Token / 会话 / 权限 / 离线队列四套 store；`PermissionStore` 提供唯一权限判定入口 `can()`（含角色权重、同权保护、最后会长判断）
- 登录、注册（注册口令 + 邀请深链）、等待分配、我的/设置、启动路由守卫、首页四 Tab
- 产出分支 `feat/client-ui-sync`（PR #11）

### B 杨睿（组长）— 分配 + 管理（全组最复杂页面 + 统筹）

- **管理页 `ManagePage`（约 1660 行，全组最复杂单页）**：部门增删改 / 注册口令查看·更换·轮换 / 招募链接生成·停用 / 重置密码（一次性临时密码）/ 会长移交（唯一会长自动禁用），全部按 `permissions` 5 个权限位驱动显隐
  > ⚠ **未修缺陷（2026-10-04 复核）**：`ManagePage.ets:1181` 用 `memberApi.list()` **不带分页**加载成员，
  > 服务端默认 `size=50` → 会长移交与重置密码的**候选列表只含前 50 位 active 成员**，第 51 名以后选不到。
- **待分配审批 `PendingApprovalPage`**：待分配列表（含招募来源、注册时间）、多选 + 全选批量分配部门 + 角色，逐条展示"成功 / 失败"并映射中文错误码
- 权限门卫页 `AdminPage` / `ApprovePage` 无权限自动跳回首页；**组长统筹**：安排分工、分支合并、提交 PR（#13）
- 14 个接口接真接口（部门写 3 · 分配 3 · 管理 2 · 注册 3 · 招募 3）；产出分支 `feat/b-member-admin`（PR #13）
- **设计稿对齐修复（本轮）**：按 13 屏设计规格逐屏审计，补齐 8 项缺口——待分配审批入口改按角色（`AssignPending`）、逾期文案「已逾期 N 天」、任务列表「共 X 项 · 全社团范围可见」、注册页「链接已失效」提示、needs_help 读取侧（首页卡片 / 任务卡片 / 任务详情阻塞块）、课题详情「子课题 · N」「本级任务 N」数量标签、会长移交二次确认、重置密码挂载
- **Logo 落地**：登录页 logo + 桌面分层图标（前景/背景）+ 启动图标

### C 刘运泽 — 任务 + 课题

- 我的任务首页（服务端分组：逾期 / 今天 / 本周 / 以后 / 无截止）、任务列表筛选、任务详情改 4 档状态（blocked 强制填原因）、新建任务
- 课题树递归展开/折叠 + 递归进度（已完成 n / 共 m）、课题详情面包屑、新建/移动/删除课题
- 日历同步专项：`CalendarSync` + `CalendarMapStore`，增/改/删同步、`lookup` 对账清理、权限被拒降级导出 `.ics`
  > ⚠ **未修缺陷（2026-10-04 复核）**：`util/CalendarSync.ets:335` 在 `due_at` 变化时以 `''` 作 description
  > 调 `doUpdate()`，会把用户已保存的日历备注**清空**（根因：`POST /tasks/lookup` 只回 `id/due_at/status/updated_at`）。
- 产出分支 `feat/task-plan-ui`

### D 郭俊杰（兼 UI）— 成员名录 + 详情 + 整体 UI

### E 李舒怀 — 设计稿对齐收尾（接手剩余缺口）

- **needs_help 写入侧**：任务详情选「求助部门 / 求助成员」+ `save()` 带 `help_dept_id` / `help_member_id` + 回显
- **部长首页 `borrowed_blocked` 区分**：本部门别人被阻塞的任务单独标记
- **P02 任务列表分页 / 加载更多**：`TaskListPage.ets:56` 写死 `{ page: 1, size: 50 }`、`:194` 页码文案写死
  `第 1 / 1 页`，第 50 条以后的任务不可达；「未完成」筛选是本地过滤已分页结果（**属缺陷，非仅缺功能**）
- **P04 课题树「全部」部门筛选**（✅ 已实现：`PlanTreePage.ets` 的 `deptFilter` / 「全部」胶囊）+ 子课题新建入口

## 三、协作方式

- Git：`main` 主分支 + 每人 feature 分支，PR 走 review 后合并
- 依赖关系：A 的 `HttpClient` 基建先行，B/C/D 等基建就绪后接真接口
- 全接口对接后端 `frontend-brief.md`，不猜接口；客户端只写 `.ets`，不建 `.cj`
